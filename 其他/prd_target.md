# 一、产品概述

## 1.1 产品背景

互联网提供了大量免费的技能学习资源。用户可以通过视频平台、社交媒体、知识社区及电子教材获取丰富的教程、实践经验和学习建议。

但这些资料往往分散于不同平台，缺乏统一的教学顺序。用户需要自行判断哪些内容适合自己、应该先学什么、如何安排练习，以及怎样将不同资料中的建议整合为系统的学习过程。

用户在掌握新技能之前，实际上需要先承担一部分教学组织工作。这增加了学习的认知负担和行动阻力。

通过前期用户访谈，已确认目标用户存在教程信息过载、学习路径不明确、难以从收藏转化为实际学习等需求。

本产品利用 AI 的信息理解、组织和规划能力，为用户提供基于已有资料的个性化技能入门指导，降低自主学习的门槛。

## 1.2 产品定位

一款基于用户自选资料的 AI 个性化技能入门 Agent。

用户上传自己搜集的学习资料并明确学习目标后，AI 负责分析资料、整理知识依赖、规划学习顺序，并将课程拆解为可以逐步执行的学习任务。

用户无需自行整理完整课程，只需按照系统提供的当前任务进行学习，并在遇到困难时向 AI 提问。

**产品核心理念：输入端追求信息丰富，输出端追求行动极简。**

## 1.3 目标用户

具备以下特征的自主学习者：

- 对某项具体技能具有明确的学习意愿。

- 已主动搜集相关学习资料。

- 对所收藏的教程、创作者或经验分享具有一定信任。

- 缺乏系统组织学习资料和安排学习顺序的能力或意愿。

- 希望以较低成本自主学习，而非立即依赖付费私教。

典型学习领域包括吉他、绘画、摄影、剪辑、设计软件、编程工具等。

V1.0 不针对特定技能开发专属课程，采用通用的资料理解与任务规划机制。

## 1.4 产品目标

**核心目标：降低用户开始学习一项新技能时的心理阻力与决策成本。**

具体目标：

1. 自动将碎片化资料组织成具有合理顺序的学习路径。

2. 将知识和经验转化为具体、可执行的学习任务。

3. 通过极简交互减少用户面对完整课程时的信息负担。

4. 基于用户可信资料提供与当前任务相关的个性化答疑。

5. 记录学习进度，使用户能够持续进行学习。

6. 尊重用户对资料来源和重要教学方案的选择权。

## 1.5 产品原则

| 原则      | 具体要求                   |
| ------- | ---------------------- |
| 用户资料优先  | 默认仅使用用户上传的资料作为教学知识来源   |
| AI 负责组织 | AI 自主完成内容分类、整合、排序和任务拆解 |
| 用户保留控制权 | 影响教学路径的关键冲突由用户选择       |
| 渐进式教学   | 课程按合理顺序逐步推进            |
| 行动优先    | 首页只突出当前最需要完成的任务        |
| 自主学习节奏  | 不强制学习时间、打卡频率或统一完成标准    |
| 来源可追溯   | 重要教学内容与原始资料建立引用关系      |

## 2.2 明确不包含的功能

V1.0 不实现：

- 学习计划生成后的资料追加、替换或重新解析。

- 根据新增资料动态重构课程。

- 资料缺口识别、待补充资料节点及补齐流程。

- AI 自主联网搜索并补充教程。

- 自动抓取任意视频内容或平台字幕。

- 完整的音视频实践指导和动作识别。

- AI 对实际技能掌握程度的客观认证。

- 每日强制打卡、连续学习奖励和排行榜。

- 社区、用户分享和付费功能。

- 根据学习反馈重新生成整个课程体系。

**V1.0 业务前提：**

用户在创建项目时一次性提交本次学习所需的全部资料。系统基于该批资料形成教学计划，生成后资料集合保持不变。

不对首次输入不足设计独立的知识补全流程。资料解析失败属于技术异常，仍需提供失败提示与重试能力。

用户可以另行创建学习项目，但不能在已生成的项目中继续导入资料。

# 三、信息架构与页面设计

## 3.1 页面结构

| 页面          | 主要内容        |
| ----------- | ----------- |
| P01 登录 / 注册 | 用户身份认证      |
| P02 我的学习    | 学习项目列表、创建入口 |
| P03 创建学习项目  | 学习目标与背景信息   |
| P04 导入学习资料  | 上传、预览、删除、提交 |
| P05 AI 分析中  | 资料处理状态及结果生成 |
| P06 教学方案确认  | 关键冲突及 AI 推荐 |
| P07 当前学习任务  | 核心学习界面      |
| P08 学习路线    | 完整课程及学习进度   |
| P09 资料详情    | 原始资料及引用位置   |

AI 答疑采用当前任务页面内的对话面板，不单独设计通用聊天主页。

## 3.2 导航结构

**未创建项目时：**

我的学习 → 创建项目 → 导入资料 → AI 分析 → 开始学习。

**已有项目时：**

我的学习 → 当前学习任务。

在当前学习任务页面，用户可访问：

- AI 答疑。

- 学习路线。

- 当前任务引用资料。

- 返回项目列表。

## 3.3 核心页面要求

### P02 我的学习

主要元素：

- 页面标题：我的学习。

- 新建学习项目按钮。

- 已创建项目列表。

项目卡片包含：

- 项目名称。

- 学习目标简述。

- 当前学习任务。

- 已完成任务数量。

- 继续学习入口。

点击项目进入上次停留的任务。

### P03 创建学习项目

表单字段：

| 字段     | 类型      | 必填  | 说明                   |
| ------ | ------- | --- | -------------------- |
| 学习技能   | 文本输入    | 是   | 例如吉他、摄影              |
| 学习目标   | 多行文本    | 是   | 例如能够弹唱简单歌曲           |
| 当前基础   | 单选      | 否   | 零基础 / 有一点基础 / 已有一定经验 |
| 学习偏好   | 多行文本    | 否   | 例如偏好实践、希望避免复杂理论      |
| 单次可用时间 | 数字或快捷选项 | 否   | 作为任务粒度参考，不用于强制排期     |

点击“下一步”进入资料导入。

除必填字段外，用户可以跳过所有可选设置。

### P04 导入学习资料

主要元素：

- 文件上传区域。

- 粘贴文本入口。

- 资料列表。

- 单项删除按钮。

- 解析状态。

- “开始生成学习计划”按钮。

交互要求：

- 支持一次选择多个文件。

- 支持分批添加文件，但只在首次计划生成前有效。

- 文件上传完成后显示文件名称和类型。

- 解析成功后标记为可用于教学。

- 解析失败显示错误原因及重试入口。

- 点击“开始生成学习计划”后锁定本次资料集合。

生成前用户可以自由增加或删除资料。

### P07 当前学习任务

这是产品的核心页面。

**默认展示内容：**

1. 当前任务标题。

2. 简短任务目标。

3. 具体操作步骤。

4. 引用资料入口。

5. “我学会了，下一步”主按钮。

6. “我还没掌握”次级按钮。

7. “我有疑问”入口。

8. 学习路线入口。

页面不默认展示完整课程目录、大量学习统计或复杂知识结构。

用户进入已有学习项目时，直接显示上次停留的任务。

# 四、详细功能需求

## F01 用户账户

### 功能说明

提供基础账户能力，保存不同用户的学习资料、课程和进度。

### 功能规则

1. 用户可以通过邮箱注册和登录。

2. 登录后进入“我的学习”页面。

3. 用户只能查看和操作自己的学习项目。

4. 用户退出登录后，受保护的项目页面不可继续访问。

5. 用户重新登录后应恢复原有数据。

### 验收标准

- 注册、登录、退出功能正常。

- 不同账户之间无法访问彼此的数据。

- 刷新浏览器不丢失已保存的学习项目。

---

## F02 学习项目管理

### 功能说明

用户可以创建多个独立学习项目，每个项目对应一项技能学习目标。

### 功能规则

1. 每个项目拥有独立的学习资料、教学计划和进度。

2. 新项目创建后进入资料导入阶段。

3. 完成教学计划生成后，项目进入学习阶段。

4. 用户可随时返回项目列表并切换项目。

5. 用户可以删除整个项目。

### 项目状态

| 状态               | 含义                   |
| ---------------- | -------------------- |
| DRAFT            | 已创建，尚未提交全部初始资料       |
| PROCESSING       | AI 正在解析资料并生成教学计划     |
| PENDING_DECISION | 存在影响教学路径的关键冲突，等待用户选择 |
| ACTIVE           | 教学计划已确认，可以学习         |
| FINISHED         | 用户已到达当前课程末尾          |
| ERROR            | 项目初始化或计划生成失败         |

FINISHED 不代表客观意义上的技能完全掌握。

### 验收标准

- 不同项目资料和状态独立。

- 项目关闭或浏览器刷新后状态保持一致。

- 项目删除后，相应学习数据不再可用。

- 删除操作需要二次确认。

---

## F03 学习目标设置

### 功能说明

收集最少必要信息，为 AI 规划提供个性化依据。

### 功能规则

1. 学习技能和学习目标为必填项。

2. 基础水平、偏好和可用时间均为可选项。

3. 不强制用户填写目标完成日期。

4. AI 不得擅自将目标扩展为完整领域的系统性学习。

### AI 使用规则

- 学习目标决定教学内容的取舍。

- 基础水平影响内容起点。

- 偏好影响教学组织方式。

- 可用时间影响任务拆解的颗粒度。

例如：

用户目标为“能够简单弹唱一首喜欢的歌曲”，AI 不应该默认要求用户先完成全部乐理知识学习。

### 验收标准

生成的教学任务应与用户声明的目标相关，不应无理由增加偏离目标的学习内容。

---

## F04 资料导入与解析

### 功能说明

接收用户自主筛选的学习资料，并转化为可供 AI 理解的内容。

### V1.0 支持格式

| 输入形式               | 处理方式               |
| ------------------ | ------------------ |
| 直接输入或粘贴文本          | 直接保存和分析            |
| TXT / Markdown     | 提取文本               |
| JPG / PNG / WebP   | 使用多模态模型进行内容识别      |
| 文本型 PDF            | 提取正文，并保留页码信息       |
| 扫描型 PDF            | 尝试视觉识别，无法可靠识别时提示失败 |
| 视频字幕文本 / SRT / VTT | 作为文字资料解析           |
| 普通网页或视频 URL        | 可作为来源备注，但不保证自动读取内容 |

**重要限制：**

仅保存 URL 不代表已经获取对应教程的正文或视频内容。

无法读取的链接不作为教学知识依据。用户可以在首次提交前补充相关文字、字幕或截图。

### 数据处理规则

每份资料保存：

- 资料 ID。

- 所属项目 ID。

- 文件名称或标题。

- 资料类型。

- 原始内容或文件位置。

- 解析后的文本内容。

- 来源信息。

- 上传时间。

- 解析状态。

原始资料与 AI 解析结果分开保存。

### 异常处理

- 文件格式不支持：提示格式限制。

- 文件损坏：提示重新上传。

- 文本无法提取：提示更换输入方式。

- AI 解析失败：允许重试。

- 部分文件解析失败：明确显示具体文件，不以失败内容作为课程依据。

### 验收标准

- 已成功解析的资料可以用于教学规划。

- 解析失败的资料不会被误认为成功。

- AI 生成内容可以追溯至对应原始资料。

- 计划生成后不提供继续上传资料的功能。

---

## F05 AI 资料分析

### 功能说明

AI 对全部初始资料进行统一理解，建立适用于教学规划的结构化知识信息。

### 分析内容

1. 识别不同资料涉及的知识与技能主题。

2. 提取教程中的实际操作方法。

3. 识别适用的初学者水平。

4. 识别知识或技能之间的先后依赖关系。

5. 合并重复教学内容。

6. 识别不同资料间的补充关系。

7. 发现影响教学路径的重要冲突。

8. 将提取结果与原始资料关联。

### AI 行为约束

**允许：**

- 对内容进行概括和归类。

- 合理调整教程之间的学习顺序。

- 将资料中的多个步骤整合为一个学习任务。

- 根据目标筛选暂时不需要学习的内容。

**不允许：**

- 将模型自行生成的知识伪装成原始资料内容。

- 擅自改写原始教程中的重要教学观点。

- 在无来源依据时补充新的专业练习方法。

- 忽略会影响学习路径的关键冲突。

### 输出结果

该模块输出内部结构化知识信息，供教学规划模块使用。

V1.0 不需要专门向用户展示完整的资料分析报告。

### 验收标准

- 能够识别核心教学内容和关联资料。

- 重复内容不应导致教学任务无意义重复。

- 生成的知识点具有来源记录。

- 重要冲突能够进入后续决策流程。

---

## F06 学习路径规划

### 功能说明

AI 根据全部资料、用户目标和基础水平，生成由浅入深的学习任务序列。

### 输入

- 用户学习目标。

- 用户基础水平。

- 用户学习偏好。

- 已解析的全部学习资料。

- 资料间的知识依赖和冲突信息。

### 输出

系统生成一个由若干学习任务组成的有序列表。

任务数量根据实际资料决定，不设置固定节数。

### 规划规则

**规则 1：目标导向**

优先安排有助于实现用户学习目标的内容，不要求覆盖全部上传资料。

**规则 2：由浅入深**

具备明确前置关系的技能，应按照依赖顺序安排。

**规则 3：实践导向**

尽量将教学内容转化为具体操作，而非仅生成知识概述。

**规则 4：资料约束**

教学步骤必须能够关联至已有资料。

**规则 5：任务粒度合理**

每项任务应围绕相对明确的学习目标，避免同时安排大量不相关操作。

**规则 6：自主节奏**

不强制按天规划，也不强制要求用户按系统预计时间完成任务。

### 单项任务数据结构

| 字段                   | 类型             | 说明      |
| -------------------- | -------------- | ------- |
| task_id              | String         | 唯一任务 ID |
| project_id           | String         | 所属学习项目  |
| title                | String         | 任务标题    |
| objective            | String         | 任务目标    |
| order_index          | Integer        | 任务顺序    |
| steps                | Array          | 实际操作步骤  |
| source_refs          | Array          | 引用的资料片段 |
| prerequisites        | Array          | 前置任务    |
| estimated_minutes    | Integer / Null | 参考用时    |
| completion_reference | String / Null  | 可选的完成参考 |
| status               | Enum           | 当前任务状态  |

### 任务示例

**任务名称：掌握正确的吉他持琴姿势**

任务目标：根据收藏教程完成一次基本持琴练习。

步骤：

1. 阅读用户上传的持琴姿势说明。

2. 对照资料中的示范调整持琴姿势。

3. 根据资料描述练习保持正确姿势。

参考资料：《吉他初学者持琴姿势指南》。

完成参考：如原始资料提供了动作检查标准，可展示对应标准；否则不强制生成。

### 验收标准

- 生成的任务按照明确顺序排列。

- 任务与学习目标存在合理关联。

- 任务步骤应具有可执行性。

- 任务步骤能够对应实际资料来源。

- 不强制生成统一学习周期或完整知识体系。

## F07 教学冲突处理

### 功能说明

当上传资料存在相互矛盾的教学建议，且差异影响实际学习路径时，AI 向用户解释冲突并提供选择。

### 冲突分类

**普通差异**

包括表达方式不同、非关键操作细节不同等。

此类差异不需要阻断学习流程。

**关键冲突**

包括：

- 同一阶段存在互斥的学习顺序。

- 两份教程给出无法同时采用的重要操作方法。

- 不同方案会显著影响后续教学路径。

### 处理流程

1. AI 识别关键冲突。

2. 提取各方案所依据的原始资料。

3. 分析方案差异及适用条件。

4. 结合用户目标给出推荐方案。

5. 用户选择采用的方案。

6. 系统记录选择并生成最终学习路径。

### 交互要求

冲突确认界面必须显示：

- 冲突涉及的教学问题。

- 方案 A 及对应资料。

- 方案 B 及对应资料。

- AI 推荐方案和推荐理由。

提供：

- 选择方案 A。

- 选择方案 B。

- **使用 AI 建议。**

“使用 AI 建议”代表用户明确授权采用系统当前推荐的方案。

### 纠错处理

如果 AI 认为用户资料存在事实错误或明显风险：

1. 向用户说明发现的问题。

2. 展示涉及的资料。

3. 说明修改建议与依据。

4. 由用户决定是否采纳。

若用户接受建议，可以将经授权的修订作为教学依据，但不得覆盖原始资料。修订内容必须标注为用户授权的 AI 建议。

涉及明显安全风险时，系统应提出警示，不应仅因用户信任来源就取消风险提示。

### 验收标准

- 关键冲突未经用户选择，不应静默采用某一方案。

- AI 必须给出推荐理由。

- 用户可以快捷选择 AI 建议。

- 用户最终选择被持久保存。

- 原始资料不会被擅自修改。

## F08 当前学习任务

### 功能说明

以当前最需要执行的学习行动作为核心页面内容。

### 页面内容

**顶部**

- 学习项目名称。

- 学习路线入口。

**主体**

- 当前任务名称。

- 任务目标。

- 操作步骤。

- 参考资料。

- 必要的完成参考（如有）。

**底部**

- 主按钮：我学会了，下一步。

- 次级按钮：我还没掌握。

- 入口：我有疑问。

### 交互规则

1. 首次进入项目，默认显示第一个学习任务。

2. 后续进入时恢复上次学习位置。

3. 默认只显示当前任务，不显示后续全部任务。

4. 用户可以主动查看完整学习路线。

5. 用户可以点击引用资料查看原始内容。

6. 用户可以随时打开 AI 答疑面板。

7. 当前任务不强制设置倒计时或完成期限。

### 状态处理

**我学会了，下一步**

- 将当前任务标记为已完成。

- 记录完成时间。

- 自动进入下一项任务。

**我还没掌握**

- 保持当前任务。

- 展示辅助选项：重新查看资料、询问 AI、继续练习。

- 不强制进入下一项任务。

**暂时跳过**

- 通过次级操作提供。

- 将任务标记为已跳过。

- 如果后续任务依赖该任务，则展示提醒。

- 允许用户确认后继续。

### 验收标准

- 用户能够明确识别当前要做的事情。

- 当前任务无需在复杂页面中查找。

- 任务切换后进度正确保存。

- 页面刷新后能够恢复当前任务。

- 用户无需强制通过考试即可进入下一项任务。

## F09 AI 个性化答疑

### 功能说明

AI 作为用户当前学习过程中的辅助老师，基于已有资料回答问题。

### 交互入口

当前学习任务页面中的“我有疑问”。

点击后打开对话面板。

### 问答上下文

系统回答时获取：

- 当前学习目标。

- 当前任务内容。

- 当前任务的引用资料。

- 同项目内其他相关资料。

- 当前用户的学习进度。

- 当前对话上下文。

- 用户已作出的重要教学决策。

### 回答规则

1. 优先使用与当前任务相关的资料。

2. 需要时检索项目内其他资料。

3. 允许对资料进行解释、归纳、举例和教学化表达。

4. 不得擅自添加没有依据的专业知识或练习方法。

5. 对关键教学建议提供资料引用。

6. 如果资料不能支持回答，应明确说明。

7. 不允许以虚构出处增强回答可信度。

### 问答示例

当前任务：练习右手拨弦。

用户提问：“为什么我拨弦时声音不清楚？”

如果用户资料中明确说明了相关原因，AI 应结合原始教程给出针对性解释。

如果现有资料没有相关指导，AI 应说明当前资料中没有足够依据，而不是直接使用其他教程中的方法。

### 验收标准

- AI 能正确理解当前任务上下文。

- 回答可以引用当前项目资料。

- 引用来源真实有效。

- 对没有充分资料依据的问题不编造专业指导。

- 同一项目的对话可持续进行。

- 对话记录在重新进入项目后仍可访问。

## F10 学习进度管理

### 功能说明

记录用户在学习项目中的位置与任务状态。

### 任务状态

| 状态          | 含义               |
| ----------- | ---------------- |
| LOCKED      | 前置条件尚未满足，暂不可直接进入 |
| TODO        | 尚未开始             |
| IN_PROGRESS | 当前进行中的任务         |
| COMPLETED   | 用户自报已完成          |
| SKIPPED     | 用户选择跳过           |

### 状态规则

1. 项目首次开始时，第一个任务进入 IN_PROGRESS。

2. 用户点击完成后，当前任务进入 COMPLETED。

3. 下一项可学习任务进入 IN_PROGRESS。

4. 用户选择跳过时记录 SKIPPED。

5. 如果用户查看已完成任务，不自动取消其完成状态。

6. 用户可以从学习路线返回历史任务重新练习。

7. 用户重新练习已完成任务时，默认保留完成记录；只有明确选择重置时才改变完成状态。

8. 所有状态变化应在服务端持久化。

### 特别说明

产品采用用户自报学习状态，不以 AI 自动推断作为技能掌握证明。

不设置强制性考试及统一的“完全学会”判定条件。

### 验收标准

- 状态变化与页面展示一致。

- 用户进度不会因刷新或重新登录丢失。

- 历史任务可查看。

- 用户可以按自己的节奏推进课程。

## F11 学习路线查看

### 功能说明

提供当前项目的完整任务列表，供有需要的用户查看整体学习方向。

### 展示内容

- 学习项目名称与目标。

- 已生成的学习任务列表。

- 每项任务的学习状态。

- 当前任务位置。

- 任务之间的必要前置关系。

### 交互规则

1. 学习路线默认不显示在核心任务页面。

2. 用户主动点击后进入路线视图。

3. 用户可以查看任意任务的概要。

4. 已完成任务允许重新打开。

5. 进入尚未满足前置条件的任务时，应展示相关提醒，不允许静默改变学习顺序。

6. V1.0 不支持通过拖拽任意重排整个课程。

### 验收标准

- 路线与实际任务状态保持一致。

- 用户能快速识别当前学习位置。

- 返回核心页面后仍恢复原当前任务。

## F12 资料来源查看

### 功能说明

保证用户能够知道当前教学内容来自哪些自己收藏的资料。

### 交互要求

任务中提供“查看参考资料”入口。

点击后能够看到：

- 资料标题。

- 资料类型。

- 对应原文或可查看的文件。

- 相关片段或页码（如可获得）。

AI 回答中的资料引用可点击打开对应内容。

### 验收标准

- 不存在指向无效资料 ID 的引用。

- 用户能够区分原始资料与 AI 的教学组织内容。

- 对于文字及 PDF 内容，尽量定位到相关段落或页码。

- 用户可以从任务页面直接返回学习界面。

# 五、核心业务规则

## 5.1 知识来源规则

系统将知识分为三种类型：

| 类型        | 定义                 | 处理方式        |
| --------- | ------------------ | ----------- |
| 原始资料内容    | 用户实际上传的知识或经验       | 可作为直接教学依据   |
| AI 教学组织内容 | 对原始内容进行归纳、排序、拆解及解释 | 允许生成，保留来源关联 |
| AI 外部知识   | 原始资料未提供的额外事实或方法    | 默认不得作为教学内容  |

用户授权接受的 AI 纠错建议需要单独记录，并与原始资料区分。

## 5.2 教学计划规则

- 一个项目对应一套初始资料集合。

- 每个项目具有一条主要教学路径。

- 教学路径由若干有序任务组成。

- 用户的学习目标优先于资料覆盖范围。

- AI 可以不采用与目标无关的资料。

- 项目生成后，V1.0 不允许修改资料集合并重新规划课程。

- 用户的日常学习反馈只影响任务状态及答疑上下文，不触发完整课程再生成。

## 5.3 用户控制权规则

以下行为必须由用户决定：

- 学习目标。

- 关键教学冲突的最终采用方案。

- 是否接受 AI 对原有教学观点的修订建议。

- 是否完成或跳过当前任务。

- 是否删除学习项目。

普通资料整理、重复内容合并和初始任务拆解不需要逐项确认。

## 5.4 数据一致性规则

- 已确认的教学冲突决策必须持久保存。

- 每条任务引用必须对应项目中存在的资料。

- 项目失败重试时不得生成重复任务。

- 计划生成成功后不能出现多个同时生效的主教学计划。

- 已保存的学习进度不能被普通问答操作覆盖。

# 六、业务流程

## 6.1 首次创建项目

```
进入产品
    ↓
创建学习项目
    ↓
输入学习目标
    ↓
批量导入全部初始资料
    ↓
提交资料
    ↓
AI 解析与分析
    ↓
生成初始教学方案
    ↓
是否存在关键冲突？
    ├── 是 → 展示方案及 AI 建议
    │               ↓
    │           用户作出选择
    │               ↓
    └── 否 ─────→ 确认最终教学路径
                        ↓
                 显示第一个任务
                        ↓
                    开始学习
```

## 6.2 日常学习

```
进入已有学习项目
        ↓
恢复当前学习任务
        ↓
查看步骤与参考资料
        ↓
实际学习与练习
        ↓
    用户选择操作
        ├── 我有疑问 → AI 答疑 → 返回当前任务
        │
        ├── 还没掌握 → 查看资料或继续练习
        │
        ├── 暂时跳过 → 提醒前置依赖 → 下一任务
        │
        └── 我学会了
                ↓
            保存完成状态
                ↓
            显示下一项任务
```

## 6.3 课程结束

当用户到达教学计划最后一项任务，并主动标记为完成时：

1. 将项目状态设为 FINISHED。

2. 展示已完成的学习任务。

3. 告知用户当前项目的教学路径已结束。

4. 允许回看历史任务与资料。

5. 不自动声称用户已完全掌握该技能。

6. 不自动生成超出原有资料范围的新课程。

# 八、非功能需求

## 8.1 性能

- 常规页面操作应有明确的即时反馈。

- AI 分析和计划生成属于异步耗时操作，应提供进度或状态提示。

- AI 答疑建议采用流式输出。

- 长时间运行的分析任务不得仅依赖浏览器持续保持连接。

- 用户刷新页面后能够查询任务处理状态。

## 8.2 可靠性

- 上传失败允许重试。

- AI 解析失败不应损坏原始资料。

- AI 生成的结构化数据必须经过字段与引用校验。

- 生成失败时允许重新运行，避免重复写入。

- 学习状态更新应具备失败提示和恢复机制。

## 8.3 安全与隐私

- AI API Key 仅存储于服务端。

- 用户文件采用受控访问方式。

- 用户数据按照账户隔离。

- 原始资料中的文字只能作为待分析内容，不得作为系统指令执行。

- 用户能够删除学习项目及相关资料。

- 不默认将用户的私人学习资料公开给其他用户。

- 记录必要的模型使用信息，但避免不必要地保存敏感内容。

## 8.4 成本控制

- 对上传文件体积设置合理的技术限制。

- 已解析内容应缓存，避免重复调用模型。

- 规划阶段避免无意义的多轮全量分析。

- 日常问答优先使用与当前任务相关的资料片段。

- 记录 Token 消耗、调用次数、耗时和错误状态。

- 对单用户及全局 AI 使用量设置可配置的限制。

## 8.5 技术选型

| 层级     | 技术方案                         |
| ------ | ---------------------------- |
| 前端     | Next.js + React + TypeScript |
| UI     | Tailwind CSS + shadcn/ui     |
| 后端     | Next.js Route Handlers       |
| 数据库    | Supabase PostgreSQL          |
| 用户认证   | Supabase Auth                |
| 文件存储   | Supabase Storage             |
| AI     | 可配置的 Gemini / OpenAI API     |
| PDF 处理 | PDF.js                       |
| 图片分析   | 多模态模型                        |
| 检索     | 数据库文本检索，按需要扩展 pgvector       |
| 部署     | Vercel                       |

技术实现应优先采用简单、可维护的工作流，不强制引入复杂的 Multi-Agent 框架。

| 维度      | 验收要求                    |
| ------- | ----------------------- |
| 来源忠实性   | 不虚构原始资料中的知识和出处          |
| 教学顺序合理性 | 基本满足资料中的先修关系            |
| 任务可执行性  | 任务具有明确可操作的步骤            |
| 目标相关性   | 教学内容服务于用户设定的目标          |
| 个性化程度   | 考虑用户基础与学习偏好             |
| 冗余控制    | 不重复安排明显相同的教学内容          |
| 冲突处理    | 关键冲突由用户确认               |
| 来源追溯    | 重要步骤能够定位原始资料            |
| 安全性     | 不将可疑、危险或缺乏依据的建议直接当作可靠指导 |

对事实正确性和来源忠实性采用关键项校验。发现虚构引用、无依据的具体教学方法或未经授权的关键修改时，应视为不合格输出，而不是仅通过综合评分抵消。

## 9.3 核心产品指标

**北极星指标：首次有效实践转化率。**

定义：用户创建学习项目后，在规定观察窗口内开始并自报完成至少一项实际技能实践任务的比例。

V1.0 重点关注以下辅助指标：

- 从资料提交到首次任务开始的时间。

- 初始教学计划生成成功率。

- 首次任务启动率。

- 首次任务完成率。

- AI 资料引用准确率。

- AI 学习计划采纳率。

- 用户自主继续学习的比例。

这些指标用于衡量产品是否真正降低了学习启动阻力，不以用户在应用内停留时间作为主要成功标准。

# 十、V1.0 完成定义

当用户能够在一个完整的 Web 应用中独立完成以下流程，即认为产品具备 V1.0 的核心业务能力：

**创建学习项目 → 输入学习目标 → 上传全部初始资料 → AI 解析与规划 → 解决关键教学冲突 → 开始第一项任务 → 基于资料向 AI 提问 → 记录学习状态 → 按顺序继续学习。**

上述流程需要具备持久化、错误处理、来源引用及用户数据隔离能力，而非仅展示静态页面或预设的演示内容。

**V1.0 的最终产品体验：**

用户将原本分散的、自己信任的学习教程交给 AI，AI 完成资料理解和教学组织，并将其转化为一个清晰的学习过程。

用户每次打开产品，都不需要重新决定应该学习什么，只需专注于当前最适合自己的一项任务。

**AI 负责复杂的信息整理，用户负责真正开始学习。**
