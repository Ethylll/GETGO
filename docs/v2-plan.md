# GETGO V2.0 开发计划

P00 已审核。实现以 [V2 原始规格](v2-spec.md)、[DEC-012～014](decisions.md#dec-012v2-学习日练习依赖与旧会话兼容) 和 [需求追踪矩阵](v2-checklist.md) 为准。V2-P01～V2-P06 是同一版本的开发阶段。

## 产品理解及范围

V2 保留资料驱动的学习起点，把主要使用场景扩展到用户已开始学习后。用户看到的是本学习日哪些可以开始、哪些需要继续练习、当前遇到的困难是否值得调整。一次性新知与重复练习可并行，用户能在有未完成事项时继续前进。练习实例完成提供行为记录，不表示已掌握。

每日任务、日期推进和依赖检查由程序完成。初始 Workflow 从用户的文字和图片生成并核验路线，继续使用现有轻量 RAG 提供来源可查的答疑。有限 Agent 只处理具有教学判断空间的决策，默认尊重原计划，能发布教学提示、澄清、自检或执行受限局部调整。确认门槛和高影响边界由程序控制。

V1 反馈和产品假设分别记录。本次保留暖色视觉、资料导入与分享给模型的提示、引用追溯、单本地会话、历史回看和三个侧栏入口。有冲突的教学事实仍沿用 V1 省略原则；V2 的高影响方案确认针对学习安排。各项非目标见矩阵 LIM。版本验收使用功能测试和有限真实模型演示，不做系统化生成质量、竞品或用户价值实验。

继续使用 `localStorage` 的版本化快照。切日按一次本地提交处理当日封存和新日生成，保存成功后提供观察机会。所有变更在应用前校验项目、活动日、操作 ID 与修订号，拒绝过时响应。普通同页操作用串行执行与幂等 ID。多标签页需要显式同源写入锁或等效的单写者保护；`localStorage` 的先读后写不能提供跨页面原子性。若保存失败，沿用保留内存与明确提示的降级策略，不将未保存的干预报告为已生效，不自动清理历史、伪造旧学习日或让失败污染快照。

## Agent 执行边界

- **观察机会。** 切学习日先提交本地状态再触发观察，用户可立即学习。计划从已有答疑请求复用「本问有新学习反馈」信号，仅决定观察机会。即使事实答疑缺少原文，也保留用户明确表达的困难。无当前任务的项目级反馈仍进入后续观察。普通问答、渲染、勾选、无变化及重复事件不启动即时观察。见 DEC-013。
- **轻量决策循环。** 复用 DeepSeek，在服务端读取有界观察及行动回执并返回结构化行动。会话仍由浏览器持有，经过共享规则校验的本地执行器实际发布提示、创建自检、提交计划补丁或登记待确认建议。下一步把真实回执交回模型，模型可继续、结束或等待。提交失败回执如实标记，等待确认也记录为尚未应用。
- **预算与停止。** 初步建议每轮最多 3 次工具动作、4 次模型决策及一段总截止时间；内部额外产生的模型核验也计入上游总量。具体数值以 V2-P04 本地和 Vercel 功能验收为准。已等待用户、结束、过期、超时、超预算或连续无进展时关闭本轮。记录未发生、拒绝、待确认或成功的真实差别，刷新不自动重放。
- **权限。** 白名单工具只允许资料检索及七项教学行动。程序复核证据 ID、任务和引用归属、依赖、影响级别与当前修订；模型的影响级别只是建议。任何工具都不得删除资料、改整体目标、写历史完成状态、虚构掌握、整份重规划或访问外部工具。用户确认也不绕过这些条件。
- **动作结果。** KEEP_PLAN 无 UI 扰动；GUIDE 实际发布带任务归属的提示；CLARIFY 在答疑留下可答可忽略的问题；CHECK_MASTERY 创建可实际完成并反馈的轻量自检；DECOMPOSE_TASK、ADJUST_PRACTICE、RESCHEDULE 提交受控局部变更或等待授权。一次行动执行成功不是学习效果，后续只根据真实实例或用户反馈再判断。
- **稳定性。** 未尝试已调整任务时默认等待，只有确实新增的严重问题或原调整有明显缺陷才例外。次数和时间作为观察事实；不存在固定阈值到教学动作的硬编码。近期和相关历史有大小上限，不新增画像、向量库或记忆服务。

## 分阶段实施

每阶段先重读 AGENTS、V2 原始规格、计划、矩阵、相关决策、上阶段记录及代码。一次只做一个阶段。结束前测试、回归、逐项自审、修复并记录证据和限制，提交一个独立 Git Commit 后停止。回复「继续」授权下一阶段，不代表人工验收。核心功能和必要测试通过且阻塞已处理即可结束当前阶段，跨阶段证据留待集成。禁止自动 Push；V2-P06 之后由用户发起最终人工验收及独立覆盖审查。

### V2-P01 协议与复验证据

- `POST /api/analysis` 的 plan 操作支持 `planVersion: 2`，不传时维持 V1。V2 返回 `oneTime` 或 `recurring`，初始状态由程序写为 `notStarted`。时长使用 `estimatedMinutes`，完成标准用 `completionCriteria`。
- 周期的 `practice` 包含 `startCondition`、`frequency`、`reviewAfter`、`longTermGoal`、`reviewCriteria`。时间用 `learningDay` 或 `elapsedMinutes`，`basis` 区分建议与原始资料。可辨认且引用有效的明确自然间隔在服务端换算，仍须经过独立核验。周期前置的 `prerequisiteGates` 可用单次入门练习完成或明确自检反馈，后者必须写明标准。
- `node --env-file-if-exists=.env.local scripts/evaluate-learning.js --v2` 实测三例均 ready 且引用可定位。键盘识别与拍手敲桌练习并行，练习频率为 Day 1 间隔、Day 3 复核，均为建议。读书卡仅生成一次性任务。排线显式 48 小时正确转为 2880 分钟，复核保持学习日建议。
- `node --env-file-if-exists=.env.local scripts/evaluate-learning.js paper vision ambiguous short conflict` 实测五例符合预期。折纸与索引卡图片形成 V1 路线；含混资料请求澄清；只有意向拒绝；局部冲突只保留纸张固定任务及提示。
- 另外向真实独立核验传入一份一次性读书卡资料及两个候选。题名填写和按封面核对返回 `supported`；把相同步骤设为重复五次即掌握、且完成标准含糊的候选返回 `unsupported`。所有真实样例只发送合成资料。
