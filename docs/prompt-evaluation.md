- Prompt 文件　`server/prompts/tutor.system.md`
- 修改原因　建立 P04.2 的首个真实答疑 Prompt。将规则与 API 调用分离，并用逐字证据约束、结构化状态和服务端校验降低无依据回答的风险。
- 对比基线　下表的「修改前」描述缺少相应约束时的预期风险，作为评测假设。首版没有可比较的历史真实模型跑分。
- 退役原因　逐字匹配曾被错误施加到正文。当前只逐字校验引用，正文可以归纳、解释和综合。

| Bad Case | 修改前预期 | v1 预期 | 回归方式 |
|---|---|---|---|
| 提问「吉他是哪一年发明的」，资料只有持琴姿势 | 可能凭常识回答年份 | 检索门槛不通过，直接返回资料不足 | `tests/chat.test.js` 检查拒答及上游调用计数 |
| 同时问持琴和调音，资料只支持持琴 | 可能补充调音步骤 | 只返回持琴依据，标记部分回答 | Mock 上游返回持琴片段，检查服务端降级 |
| 引用存在，但回答追加原文没有的断言 | 单独校验引用 ID 会放行额外事实 | 拒绝整条答复 | Mock 上游返回合法引用和额外断言 |
| 不存在的来源、伪造片段、检索范围外的原文 | 可能展示无法追溯的引用 | 拦截引用及相关答复，返回资料不足 | Mock 上游构造三种无效引用 |
| 两份资料对同一动作有不同要求 | 可能擅自采用其中一份 | 标记冲突并并列两份证据 | Mock 上游构造双来源冲突和缺一方证据的结果 |
| 资料中写有改变系统规则的指令 | 可能误把资料指令当作系统指令 | 将资料当作数据处理，避免执行或披露规则 | 检查 Prompt 文件和请求边界，真实模型鲁棒性另行验收 |

### 本版回归结果

- `node --test` 通过全部 41 项测试。上表前五类 Bad Case 使用模拟上游验证，资料内指令场景验证了独立 Prompt 加载和系统指令与资料数据分离。
- 使用吉他演示文本实际调用 DeepSeek，接口返回 HTTP 200，结果状态为 `answered`，一条引用与演示原文逐字匹配。真实模型的冲突判断和对抗样例仍待单独评测。
- 使用模拟上游完成 Edge 浏览器回归，覆盖回答、追问、拒答、错误反馈、引用定位、任务历史隔离、刷新恢复及手机宽度。直接请求 Prompt 文件返回 HTTP 403。

## v2 · 2026-11-20 · BC-001 答疑过度拒答 · 历史版本

- Prompt 文件　`server/prompts/tutor.system.md` 和 `server/prompts/tutor.verify.md`
- 修改原因　人工验收反馈资料内问题也经常被拒答。首版复现时，「如何持琴」命中一段资料，但将「把乐器放稳」改写为「先稳住琴身」会被正文逐字比较拦截。「弹的时候琴身怎样才不会晃」未命中资料，拒答发生在模型调用前。V1 原本已可返回多段，问题在于匹配特征不足。
- 调整内容　答复允许归纳、解释、简化和组合证据，引用仍需逐字匹配本次检索结果。服务器先校验来源、引用及数值，再通过独立 Prompt 核对事实、建议、条件和冲突。检索结合中文词、短语、同义表达及覆盖率，保留相关度、命中项和位置供服务端排查。

| Bad Case | v1 行为 | v2 预期与 Mock 回归 |
|---|---|---|
| 原问命中，答案使用自然释义 | 只允许逐字摘录，改写被拒绝 | 接受有依据的释义，原文引用保持逐字准确 |
| 「琴身怎样才不会晃」与页面资料措辞不同 | 未命中 | 召回持琴相关片段，保留短语命中和评分 |
| 问题同时涉及持琴和调音 | 词面相同的片段排序靠前，可能挤掉其他子问题的证据 | 为各子问题保留首个相关片段，有两份依据时组合回答，仅有一份时标记部分回答 |
| 无相关资料、伪造引用或在合法引用之外追加事实 | 逐字摘录限制拦截回答，引用另行校验 | 无资料时不上游调用，伪造引用在语义核对前拦截，越界断言由核对拒绝 |

### 本版回归结果

- `node --test` 通过全部 44 项测试，包括原有 P01–P03 路径及 BC-001 回归。构建和 `git diff --check` 通过。
- 真实 DeepSeek 复验使用吉他演示资料「把乐器放稳。让琴身贴近身体，用右前臂轻扶琴身，避免琴身晃动。练习前先放松肩膀。」直接运行应用的服务端答疑处理器。

| 问法 | 实际结果 |
|---|---|
| 如何持琴？请用自己的话简单解释。 | HTTP 200，`answered`，生成和核对各一次。正文使用自然语言，一条引用逐字匹配 |
| 弹的时候琴身怎样才不会晃？ | HTTP 200，`answered`，生成和核对各一次。正文使用自然语言，一条引用逐字匹配 |
| 吉他是哪一年发明的？ | HTTP 200，`insufficient`，零次上游调用 |

- 关键词检索仍可能漏掉表达差异较大的内容。语义核对仍有误判风险，并增加一次上游调用。真实试跑验证了本表三种问法，冲突和伪造引用场景使用 Mock 回归。
- 全链路审计补记　v2 的自然语言即时答复可通过服务端，旧存储仍会丢弃与摘录不完全相同的答复。表中的 Mock 只验证程序收到指定输出后的行为。

## V2-P04 学习 Agent · 2026-11-21

- `learning-agent.system.md` v1 新增依据当前和历史学习事实选择合法行动的协定。稳定、有明确困难和有时间限制的场景可以走不同分支。候选教学内容需要独立核验，模型只从真实回执了解是否生效。
- 复验中，模型有时只返回 `{"type":"wait"}`。服务端允许这类无副作用的终态，并保存不添加学习事实的状态说明。调整与教学动作仍要求完整结构和有效依据。另一轮试跑重复提出同任务指导，执行器加入无新学习记录时的重复保护，Prompt 同步要求读取已发布回执。
- 真实功能复验运行 [合成场景脚本](../scripts/verify-learning-agent.js)，通过本地 Vercel 路由打开保持计划、基于资料的指导及 6 分钟缩为 3 分钟的练习调整。脚本检查真实落盘、原计划仍保留、实际任务安排变化，以及调整之后是否仍等待实际练习。一次真实调整先收到 `invalid_steps`，下一步修正后应用，而非在拒绝时修改计划。
- 程序使用固定模型响应验证权限、回执、等待、确认、无新证据防重复、撤销和超时。真实示例用于确认流程可运行，未开展规模化效果或用户价值评测。

## V2-P06 自然时间与复核边界 · 2026-11-21

- `analysis.plan.md` 与 `analysis.review.md` 的 V2 段从 v2.0 更新为 v2.1。合成排线复验曾只保留一次性任务；另一次检查发现首轮规划重复列出相同练习，并把下次练习的 48 小时也写成复核。核验曾放行该用途混淆。
- 规划明确第一次实践属于同一个周期任务，核验独立检查是否存在必要的准备动作。程序根据逐字原文区分明确的下一次练习间隔和复核；明确摘录只支持下次练习时，复核单独标记为学习日建议。
- 程序测试核对逐字来源、2880 分钟与推荐复核。通过真实 DeepSeek 复跑既有三项 V2 合成案例，独立键盘和节奏并行、读书笔记纯一次性、排线自然时间三类均符合预期。模型选取和核验仍会随资料和上游输出变化。本次只验证既有功能场景。
