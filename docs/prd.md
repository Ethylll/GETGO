# GETGO 产品需求｜V2.0

GETGO「开练」是面向技能自学者的 Web Demo。把收藏的资料交给 GETGO，就能从可执行的一步开始，并在之后的学习日继续练习、提问和调整安排。本版本仍面向本地演示和作品集，产品取舍见 [决策记录](decisions.md)，原始迭代要求见 [V2 规格](v2-spec.md)。

## 1. 问题、用户与产品原则

V1 帮助已经收集教程、截图和笔记的用户从零散资料中找到起点。项目记录的定性反馈是，用户认可整理路线的价值，但多在尝试几个步骤后停止使用。仓库没有足以独立核实人数、比例或留存的原始记录。产品分析认为，单线推进难以表达需要多次练习的技能，静态计划也难以回应学习中暴露的困难。V2 对持续学习行为的改善尚待验证。

V2 帮助用户判断今天学什么、哪些动作值得持续练，以及遇到困难时能否继续。用户无需填写技能名称、学习目标或基础水平。学习内容以本次资料为边界，任务、教学建议和事实性答疑可追溯。用户控制学习节奏和高影响变更。单次完成、自检和长期掌握分别表达。

## 2. 核心范围

| 优先级 | 交付 |
| --- | --- |
| P0 | 一次性导入文本、真实主题识别、独立核验的初始学习路线、一次性任务和周期练习、今日学习、历史回看及刷新恢复。 |
| P0 | 三个学习入口、任务级与项目级资料答疑、明确的资料范围和缺口、可定位的原始来源、部分识别失败与关键冲突处理。 |
| P0 | 有限自治 Learning Agent、实际行动回执、调整前后差异、澄清、高影响确认、撤销和保留历史的恢复。 |
| 非阻断支持 | 保留导入图片、真实读图与以提取文字生成计划的能力。少量样例生成失败作为 Demo 限制记录。 |
| 可选 P1 | 文本型 PDF 提取、影响具体学习操作的冲突解释与用户方案选择。 |

项目保留单一浏览器会话和单次资料导入。账号、多项目管理、云同步、数据库、追加资料、整体再生成、外部网页或视频抓取与转写、日历与推送、后台定时任务、技能认证与专业评分、社区和商业化均在本版本范围之外。外部链接只有用户粘贴的文字会被读取。架构采用单个有限 Agent 和轻量 RAG，向量数据库、Embedding、微调、知识图谱、复杂记忆系统及多 Agent 协作留在版本范围之外。

## 3. 用户流程与界面

### 3.1 资料导入与真实分析

首页以米黄、燕麦和柔棕为主，显示「开练 | GETGO」、Slogan、上传区、文字入口及必要操作。资料添加后才显示列表。用户可以删除资料、展开折叠列表，选择「我要开始！」。空提交会在按钮处提示至少添加一份资料。

一次最多导入 10 份原始资料。每段文本独立计数，支持多张 PNG、JPG、WebP 图片，单张最大 5 MiB，界面显示 5 MB；浏览器检查格式、文件内容和可读性。上传识别时客户端会尝试将超过 4 MiB 的图片压至服务端允许的范围。一次分析的原文及提取文字合计最多 60,000 字符，超限显式提示。

分析页按实际流程显示资料读取、主题识别、整理和生成。读图或资料部分失败时列出原因，经用户确认才使用成功项。主题已有教学内容但含混时可简短澄清。无可靠主题或有效路线时给出说明并允许返回。出现影响学习顺序或操作的关键冲突时省略受影响任务：有独立有效路线就附提示继续，否则提示无法生成可靠计划。P1 的冲突方案选择仍为可选，以原始资料为边界。

### 3.2 今日学习

有效计划进入 `Day 1`，页首说明资料支持范围、已识别的内容缺口和冲突省略提示。默认展示当前学习日、主题、预计时长、必做完成情况，并分别列出一次性任务、周期练习和选学。页面聚焦当前任务，显示目标、2～5 个动作步骤、来源和单次完成标准。

- **一次性任务**按前置关系提供，完成后默认不重排。合法的巩固行动以新任务 ID 创建，原完成时间照常可查。
- **周期练习**含启动条件、频率、建议复核、持续目标及停止、减量或调整参考。只有原文明确支持的自然间隔才按模拟分钟排程。资料未给出的频率和复核按模拟学习日标为 AI 教学建议。练习间隔和复核依据分开核验。周期练习与无依赖的新知识可并行，后续任务仅依据明确的入门动作或用户自检反馈解锁。
- **今日配额**默认 30 分钟、最多 5 项。内部配额至少容纳一项最长的有效任务。任务时长由初始 Workflow 决定。用户完成任务后，同日新解锁仅可在剩余配额内作为选学。
- **用户主动推进**。每次点击页角「下一日」增加 24 小时模拟时间，即使未完成必做也能随时操作。48 小时间隔从 Day 1 推进到 Day 3 即满足。切日封存原日任务状态和问答，未开始或进行中的任务记为该日未完成，进行中仍表明曾开始。开放日的未完成任务暂不作最终判定。漏练不会增加后续练习量，也不会自动推断原因。真实操作时间只用于技术记录，不存在后台自动跨日。 [DEC-019](decisions.md#dec-019demo-采用手动推进的模拟自然日)

### 3.3 学习工具与反馈

正式学习界面保留三个主动打开的图标入口，默认收起。整个核心流程适配手机及桌面浏览器。

| 入口 | 交互 |
| --- | --- |
| 完整学习路线 | 查看总体目标、当前阶段、已完成的一次性任务、后续内容、周期练习及历史学习日。历史回看保留当时的任务与状态，实际进度独立。 |
| 学习资料 | 查看所有本批资料、类型、处理状态、关联任务、完整原文或原图。点击学习任务、步骤、答疑或指导的引用，可定位并高亮原文片段。刷新后原图缺失时提示，提取内容和有效引用仍可使用。 |
| AI 答疑 | 对当前任务提问、连续追问，或在没有当前任务时进行项目级答疑。对话按发送时的项目、学习日、任务实例关联，切换、重开或刷新后仍可回看。只有本次资料支持的部分才可作事实性回答。 |

教学指导融入今日页，附任务和可定位来源。高影响建议可查看原因、受影响任务与变更前后，接受后才应用，拒绝保留有效安排。调整显示当日实际影响或后续生效范围。已经开始的任务如因拆解、延期或关键前置变更而暂不可执行，保留开始记录和问答，完成命令也受前置与排程约束。关联学习记录产生前可撤销，之后通过新变更恢复并保留旧记录。澄清复用答疑，可暂缓再从历史回复。保持计划时直接继续学习。

## 4. 真实模型与确定性程序

### 4.1 初始 Workflow

文本保留原文。图片由现有 DeepSeek 多模态读图能力读取，区分可见文字和可判断图示。统一前端分析入口调用 Vercel，先识别主题，再规划知识点、任务类型、前置、周期、时长与入门任务。主题澄清只用于识别语境。

模型输出结构化 JSON；服务端检查任务 ID、2～5 个步骤、前置关系、起点和引用，并用单独请求核验任务类型、可执行性、单次完成标准、周期安排、来源及冲突。清除无依据、冲突或带无效前置的任务。浏览器用原批次资料再次校验。正式流程使用真实模型，Mock 只用于测试或明确标识的演示。

### 4.2 资料内答疑

现有轻量 RAG 以关键词、任务相关段落、邻段和多来源构建有界候选，再由 DeepSeek 结合当前问题和有限对话做语义重排。任务和历史只帮助理解语境。合格回答可解释、归纳或综合多段资料。模型输出结论及对应出处，程序校验来源 ID、检索片段和逐字摘录，另一步逐项核对事实、条件、单位与冲突。部分有依据时只展示通过项，资料外或证据不足时明确说明。来源限于本批上传的原文或提取文字。

### 4.3 有限自治 Learning Agent

调度、任务推进、历史保存、动作权限和计划修改由程序负责。切日保存后、任务级新反馈或真实澄清回复保存后给 Agent 观察机会。项目级学习反馈纳入后续观察。普通答疑、浏览、勾选及重复提交不触发即时观察。

Agent 可读取有界的当前与历史学习实例、学习日及模拟分钟、未完成与已开始状态、周期及依赖、近期对话、已提供帮助、初始／有效计划、资料片段、教学变更及后续反馈。封存日的连续未完成是行为证据，模型根据问答与实际表现自主判断原因及行动，默认保持计划。没有足够证据时可等待或澄清。次数、自评和动作成功不能证明技能掌握。

| 行动 | 可以造成的实际结果 |
| --- | --- |
| 保持计划、资料检索 | 按原安排继续；按需在本项目原文中寻找证据。 |
| 指导、澄清 | 发布有依据且关联任务的短提示，或在答疑中留下可回答的问题。 |
| 拆解任务、调整练习、重排 | 在保留原始目标和历史的条件下拆小步骤、调整周期属性、延期或优先安排，以及加入选学巩固。 |
| 建议自检 | 在配额内创建具体可做的选学自检，记录可观察反馈或自评。 |

服务端每次只产生一个判断或独立核验。浏览器校验并执行白名单动作，保存真实回执和当日实例影响交回模型，模型自主判断继续、结束或等待。每轮上限 3 次工具、4 次决策和 5 次含核验的模型请求，总时限 34 秒。已开始任务的实质变更、拆解带来的关键依赖变更等待确认。执行器按完整本地相关变更记录保护尚未实践的安排，并在无新证据时阻止已拒绝的近似提议。Agent 不可用、超时、返回非法动作或超出预算时，仍按当前有效计划学习和推进，轮次保存脱敏失败类别。

## 5. 数据、接口与隐私

| 数据／接口 | 实际结构与职责 |
| --- | --- |
| 前端和服务端 | React + Vite + JavaScript + Tailwind CSS；服务器端为 Vercel Functions，模型沿用 DeepSeek。 |
| `/api/analysis` | 图片实际字节、主题识别、路线规划；新会话请求 `planVersion: 2`，旧协议继续兼容。 |
| `/api/chat` | 当前任务或 `scope: "project"` 的资料内答疑，返回核验后正文、状态及精确引用。 |
| `/api/learning-agent` | 接收有限观察、执行回执或待独立核验的内容，返回一次结构化判断。真正写入状态由浏览器完成。 |
| 学习计划及日记录 | `plan` 保持初始路线，`effectivePlan` 保存局部变化。`days[].simulatedMinute` 每日递增 1440。`days[].instances` 保存任务快照、执行状态、修订与真实操作时间。 |
| 消息与教学记录 | `messages` 保存原项目、Day、实例、问答及引用，澄清关联原问题与实际回复日。`agent` 保存轮次、脱敏错误、执行回执、当日实例影响和变更前后差异。 |

`localStorage` 使用版本化的单项目快照。刷新恢复实际学习日、完成情况、计划及问答，当前打开的面板和回看位置为临时状态。旧 V1 会话以兼容界面保持线性进度、资料和问答，不补造学习日或历史时长。数据损坏或版本未知时保留旧记录，提示经用户操作再重新开始。保存失败时给出提示；Agent 变更只有写入成功才报告生效。

原图片 File 与临时 URL 只在内存中使用。保存原始文字、提取文字和出处。清理站点数据后记录可能丢失，无法跨浏览器或设备恢复。首次进入今日学习时显式说明，推进学习日或提交学习反馈可能将有界的学习记录、问答和资料片段发送给 DeepSeek，以判断是否需要教学帮助。首页、答疑和澄清编辑区继续说明各自的发送内容。实际数据处理以 DeepSeek 的条款为准。上传内容与消息中的指令不会改变系统权限。API Key 只从服务端环境变量读取，浏览器只访问项目接口，请求有输入限制、基础频率限制和超时。

## 6. 验收与交付

最小交付包括以真实自选资料开始、按模拟学习日继续练习、提问及回看来源、获得合规调整和刷新恢复。验收按 [105 项需求矩阵](v2-checklist.md) 和 [统一人工验收指南](v2-plan.md#最终统一人工验收指南) 执行。

- 输入回归覆盖 10 份及图片格式／大小、真实 OCR、部分失败确认、主题澄清、内容缺口、有独立证据时省略冲突任务和无有效路径。
- 学习回归覆盖一次性与周期并行、模拟 48 小时间隔、进行中前置保护、下一日、选学、历史回看和旧会话读取。
- 答疑回归覆盖直接提问、同义或跟进问法、引用定位、资料不足、不实引用拦截、任务／项目归属、延迟回复和刷新恢复。
- Agent 回归覆盖保持、局部教学与实际改动的真实模型路径，受控测试覆盖高影响确认、去重、回执、超时、过期、撤销和历史保护。无 Web Locks 时跨标签页写入仍有竞争风险。
- 测试结果区分程序、有限真实功能案例和人工验收。下一阶段再评估持续学习、周期安排、介入时机、行动选择、困难缓解、计划稳定性、调用成本和耗时。此版本不报告系统化模型评分或用户价值结论。
