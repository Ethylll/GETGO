# PRD V1.0｜从收藏到学会——学习资料整理与引导 Agent（Demo）

| 项目 | 内容 |
|---|---|
| 文档版本 | V1.0 · 作品集 Demo 版 |
| 产品形态 | 响应式 Web 应用（PC、手机浏览器） |
| 产品目标 | 快速实现可交互、可演示的 AI 产品，用于 AI 产品实习作品集 |
| 核心用户 | 已收集新技能或新领域的学习资料，却不知道从哪里开始、如何安排学习顺序的人 |
| 核心理念 | **用户交付资料，Agent 整理路线，界面聚焦当前一步** |
| 开发原则 | 真实 AI 能力、完整最小闭环、低工程复杂度；不追求商业化产品完备性 |

## 1. 产品定义

### 1.1 问题与机会

目标用户已经收集了不少关于某项新技能或新领域的教程、截图和笔记。这些资料是他们主动筛选的学习来源，但内容零散、繁杂且深浅不一。用户不知道从哪里开始，也难以判断哪些内容应该先学。整理资料和规划顺序的成本推迟了实际学习。此需求已通过前期用户访谈验证，访谈证据及结论单独保存在作品集研究材料中。

### 1.2 产品定位

产品是一个学习资料整理与引导 Agent。用户交付自己收集的资料，Agent 识别学习主题、整理知识点和前置关系，形成由浅入深的学习路线，并推荐现在最值得开始的一项可执行任务。用户无需预先制定学习计划、设定最终目标或判断自己的基础水平。学习过程中可查看资料来源并获得基于资料的 AI 答疑。

**一句话描述：**把你收藏的资料交给 Agent，它会帮你找到第一步，带你一步一步开始学习。

**不是什么：**不是通用知识库、自动制课平台、思维导图/刷题工具，也不是替用户决定哪份教程“更权威”的 AI 专家。

### 1.3 不可妥协的原则

1. **Source-first：**学习任务和事实性答疑均以用户本次导入的资料为依据。AI 可以归纳、排序和拆解任务。答疑中的事实性结论必须可追溯到原始资料。
2. **Next Action：**Agent 选择资料支持的入门起点。默认只呈现当前任务，完整路线由用户主动打开。
3. **Human-in-control：**Agent 不得静默决定影响学习顺序或具体操作的关键资料冲突。P0 暂不生成受影响的任务，仅在剩余内容能形成有效学习路径时继续，并提示冲突导致的省略。P1 由 AI 解释并推荐，最终由用户选择，提供“使用 AI 建议”。
4. **Learning by Doing：**优先形成动手实践步骤，而不是大段理论摘要。
5. **Self-paced：**不强制打卡、不设固定学习周期，不宣称用户完成任务即真正掌握技能。

## 2. V1.0 范围

### 2.1 最小业务闭环

**进入首页 → 一次性导入资料 → Agent 识别主题、整理知识点与前置关系 → 生成有序路线并选择入门起点 → 进入正式学习界面，默认展示当前任务 → 执行 2–5 个步骤 → 标记完成并进入下一项。**

学习中可主动打开 AI 答疑、完整学习路线或学习资料。刷新后恢复当前任务、进度和答疑历史。

V1.0 **以一次导入的资料作为本项目的全部资料**。生成计划后不支持继续上传、资料补齐、重新规划或自动网络搜索。学习路线仅覆盖资料有依据的内容。开始第一项任务前说明当前资料能支持的学习范围，以及已识别的内容缺口（如有）。

### 2.2 功能范围与优先级

| ID | 功能 | 优先级 | V1.0 要求 |
|---|---|---|---|
| F01 | 识别主题并创建单个学习项目 | P0 | 从导入资料识别主题并自动创建项目。主题无法可靠识别时可简短澄清 |
| F02 | 资料导入与识别 | P0 | 粘贴文本、上传图片/截图；提取可用文本；PDF 为 P1 |
| F03 | AI 整理学习路线 | P0 | 从资料梳理知识点和前置关系，生成有序任务、可执行步骤和入门起点。任务及依赖不同资料的步骤须有有效引用。省略受关键冲突影响的任务 |
| F04 | 当前学习任务 | P0 | 默认只展示当前任务，完成后进入下一项。第一项任务开始前说明资料支持的范围及已识别的内容缺口 |
| F05 | 当前任务资料内答疑 | P0 | 通过真实 DeepSeek 理解口语、指代和追问，从本次导入资料中重新检索证据。可解释、归纳、综合多段资料，逐项核验结论和引用，保留有依据的部分。无依据时说明。重开面板或刷新后恢复原回答和引用 |
| F06 | 进度与本地保存 | P0 | 上一步/下一步、标记完成；刷新后恢复 |
| F07 | 浏览学习资料与追溯引用 | P0 | 浏览本次全部资料、区分类型、查看原始内容及关联任务。任务和答疑引用可定位到对应资料和片段 |
| F08 | 关键冲突人机决策 | P1（加分） | AI 给出方案、推荐理由，用户选择或“使用 AI 建议” |
| F09 | 主动查看完整学习路线 | P0 | 从侧边栏打开，查看完整任务顺序和完成状态，标记当前任务，支持回看已完成任务 |
| F10 | 文本型 PDF 提取 | P1 | 可解析后按文本资料处理 |

**本轮交付：**完成并验收 F01–F07、F09。P0 正式规划检测关键冲突并省略受影响任务。F08 的冲突解释和用户决策、F10 为可选 P1。F08 可用固定 Mock 案例演示交互。

**不做：**登录注册、多用户体系、多项目管理、服务端数据库、复杂知识图谱、独立向量数据库、自动抓取网页/视频、视频转写、补充资料、动态课程重构、能力自动测评、社区打卡、管理后台与支付。

**范围说明：**在页面与宣传中应明确图片内容可被 AI 理解；网页/视频 URL 不视为已解析内容，V1.0 不将“粘贴链接即可读取任意平台教程”作为能力承诺。

## 3. 页面与交互

### P01｜资料导入首页

- 首页只保留产品名称、简短介绍、占据最大视觉面积的资料导入区、上传图片和粘贴文字入口、必要按钮与限制提示。添加资料后才显示列表，包含名称、类型、处理状态和删除操作。
- 首页省去技能名称、学习目标和基础水平表单，同时省去侧边栏、进度、统计卡片等正式学习界面内容。
- 主要 CTA：**“生成我的第一步”**（提交前可增删资料）。
- 校验：没有有效资料时禁用生成并说明原因。支持多段文本和 PNG/JPG/WebP 图片。一次最多 10 份资料，单张图片不超过 5 MB。格式不支持或超限时提示对应原因。
- 识别失败时列出失败资料及原因。部分资料识别成功时，用户可确认仅使用成功资料继续。剩余资料不足以形成有效学习路径时，明确提示无法生成。
- 生成时展示真实处理阶段：读取资料 → 识别主题并整理学习顺序 → 生成学习任务。主题无法可靠识别时，可在分析过程中提出简短澄清，等待用户回应后继续。仍无法确定主题时提示无法可靠生成。进度以阶段表达。

### P02｜正式学习界面与当前任务

仅在资料分析完成、生成有效路线后进入正式学习界面。开始第一项任务前，以简短说明呈现资料支持的学习范围和已识别的内容缺口。因关键资料冲突省略任务但仍有有效路径时，提示“部分内容因资料冲突未纳入本次学习计划”。无法形成有效路径时在 P01 提示无法生成可靠计划。

默认信息层级：

1. Agent 识别出的学习主题（较弱视觉层级）。
2. **“现在只需要做这件事” + 当前任务标题**（最突出）。
3. 任务目标和 2—5 个可执行步骤。
4. 当前任务的有效资料来源（可展开查看原文片段）。不同步骤依赖不同资料时，在对应步骤展示引用。
5. 主要按钮：**“完成，进入下一步”**。
6. 次要操作：**“上一项”**。答疑、完整路线和资料浏览通过侧边栏访问。

侧边栏只在正式学习界面出现，包含三个独立入口，面板默认收起。关闭面板后回到当前学习任务。

- **完整学习路线**：展示完整任务、任务顺序和完成状态，明确标记当前正在进行的任务。用户可回看已经完成的任务，回看时保留当前学习位置。
- **学习资料**：列出本次导入的全部资料并标注类型，包括未成功识别的资料。可查看原始文本、当前会话可用的原图及与任务的关联（有对应关系时）。任务和答疑引用可定位到对应资料与相关片段。刷新后的原图回看按 5.2 节处理。
- **AI 答疑**：打开 P03，默认围绕当前任务，保留本次会话记录。

不默认展示完整课程目录、知识图谱、大段摘要、积分或倒计时。最后一项任务完成后显示“这次资料支持的任务已完成”，允许回看；不声称用户已完全学会该技能。

### P03｜AI 答疑面板（P04 开发阶段）

- 从正式学习界面的“AI 答疑”入口打开，显示当前任务标题及本次会话消息。
- 用户提问后，以当前任务为语境，事实依据仅来自本次导入的学习资料。有依据的回答提供可点击的来源和相关片段，并能追溯到原始资料。程序拒绝展示无法验证的引用。
- 资料没有答案时显示：“在你提供的资料中没有找到足够依据，因此无法可靠回答这个问题。”可追加简短说明，但不擅自引入其他教程。
- 用户关闭后重新打开面板时保留本次对话。答疑历史随学习会话保存在 `localStorage`，刷新后再次打开面板时恢复历史消息和有效引用。

### P04｜冲突确认（P1）

仅当模型判断不同资料对**实际学习顺序或具体操作有实质影响**时触发。显示：冲突点、方案 A/B、各自来源、AI 推荐及理由。操作：**选择 A / 选择 B / 使用 AI 建议**。决策后确认课程；不修改原始资料。无关键冲突时不展示此页。

> 可用固定 Mock 案例演示冲突确认交互，并标明为模拟演示。P0 识别与省略按 Workflow A 执行；供用户选择的冲突解释与决策交互属于 P1。

### 3.1 视觉风格

整体采用简洁、温暖、安静的个人学习空间风格。以米黄色、燕麦色和柔和棕色为主，使用温暖背景、适当留白和清晰的信息层级。避免大面积纯白或纯黑、科技蓝、复杂渐变、发光和过度装饰。避免复杂 SaaS Dashboard 布局和幼稚的卡通化设计。桌面端优先，核心流程也应适配手机浏览器。

## 4. AI 核心能力与规则

### 4.1 Workflow A：资料理解与教学规划（P0）

**输入：**本次资料的 `source_id`、名称、原文或提取文本，以及仅在主题不明确时获得的简短澄清。澄清用于判断主题，事实依据仍来自资料。

**流程：**

1. 文本资料直接保留原文。DeepSeek 多模态读取真实上传图片，分别提取可见文字和可见图示内容。部分识别失败时列出具体原因，等待用户确认后再使用成功资料规划。
2. 为每份资料分配稳定 `source_id`，保留标题和原文/提取内容。
3. DeepSeek 从成功资料识别主题、领域和资料关系。已有教学内容但主题含混时简短澄清；只有意向或其他无用资料时提示不足。主题确定后提取知识点和可执行动作，分析前置关系、检测冲突、排序并选择入门任务。
4. 服务端检查模型 JSON、任务 ID 唯一性、2–5 步、前置关系、起点和任务及步骤的逐字引用。独立核验任务受资料支持的程度及冲突。剔除未通过任务和依赖项。浏览器用本批原资料再次核对结果。
5. 返回主题、完整有效路线、入门任务及来源片段，同时返回资料支持的学习范围和已识别的内容缺口。因关键冲突省略任务时，返回对应提示。无法形成有效路径时提示无法生成，不以模板课程冒充资料驱动结果。

**核心 JSON 示例（概念结构，实际开发可调整字段名）：**

```json
{
  "topic": "吉他入门",
  "entry_task_id": "task_1",
  "supported_scope": "持琴与姿势调整",
  "coverage_gaps": ["资料未提供调音步骤"],
  "tasks": [
    {
      "id": "task_1",
      "title": "练习正确持琴",
      "objective": "根据资料完成第一次持琴练习",
      "steps": [
        { "text": "查看姿势示范" },
        { "text": "按示范调整持琴姿势" }
      ],
      "source_refs": [
        { "source_id": "src_1", "excerpt": "来自原始资料的相关文字" }
      ]
    }
  ],
  "conflicts": []
}
```

**关键规则：**

- AI 可以将多个来源整合成一个任务，但不得将未经来源支持的专业教学方法当作事实。
- AI 的教学排序属于推理，可以进行，但不可把推理伪装成原作者的原话。
- `excerpt` 必须能在对应资料的原文或提取内容中校验。校验失败时移除无效引用或在限定次数内重新生成。每项任务必须保有有效引用，不同步骤依赖不同资料时须提供步骤级有效引用。缺乏有效依据的任务不能展示为可靠的学习任务。
- P0 规划发现影响学习顺序或具体操作的资料冲突时，暂不生成受影响的任务。若剩余内容仍能形成有效学习路径，则继续生成，并提示“部分内容因资料冲突未纳入本次学习计划”。若剩余内容不足以形成有效路径，则提示无法生成可靠计划。
- 图片的提取结果需保留对应图片 ID；图片内容不确定时避免输出断言。
- 首次生成目标是**可执行的任务序列**，不是全面完整的课程。

### 4.2 Workflow B：当前任务答疑（P0）

**输入：**用户问题、当前任务、资料原文或提取文本、最近对话。任务和对话用于理解提问语境。

**流程：**

1. 每轮从本次原始资料切分并检索。关键词、任务相关段落和少量邻段组成有界候选，再与 DeepSeek 的语义相关性排序融合。当前任务和最近同任务对话帮助解析指代，不作为事实依据。
2. 由 Vercel Serverless Functions 调用 DeepSeek，只将选定证据段作为事实依据。模型将教学化回答拆成可单独核验的结论或步骤，各自提供来源 ID、片段 ID 和原文引用。
3. 服务端逐项核对来源和原文，并核验解释、推论、数量、单位和条件有无资料支持。正文可用自然语言改写，引用逐字准确。资料冲突时如实呈现双方依据。
4. 仅展示通过核验的结论，支持部分回答；没有通过核验的结论时说明资料不足。保留原始正文、状态和有效引用以供重开面板、刷新和后续追问。

**规则：**事实性回答仅使用用户本次导入的资料。预训练知识、外部搜索结果、对话中的未经验证信息均不可用作事实依据。按 DEC-006，P04 直接实现正式答疑链路，Mock 用于测试和模拟异常场景。

### 4.3 Workflow C：冲突决策（P1）

可选 P1 在规划 JSON 中附带冲突候选。只有影响具体教学路径的冲突才触发用户选择，普通表达差异直接忽略。AI 给出建议及依据，用户确认后可记录决策，用于生成或确认最终任务顺序。保留原始资料。P0 按 4.1 节省略受影响任务。

### 4.4 Agent 边界

系统可以按资料和学习状态决定生成任务、提供答疑或（P1）等待用户决策，但首版主要是轻量 **LLM Workflow + 状态管理**。作品集应准确描述实际实现，**不为了营销而声称采用 Multi-Agent、自主浏览或长期记忆**。

## 5. 数据与技术方案

| 层级 | Demo 选型 | 原因 |
|---|---|---|
| 形态 | 响应式 Web App | 链接即可演示，PC/手机可用 |
| 前端 | React + Vite，使用 JavaScript | 支持本地运行和响应式交互 |
| UI | Tailwind CSS | 保持页面和组件样式一致 |
| Service | 浏览器经统一分析 Service 调用 `/api/analysis`，经 `/api/chat` 答疑。正式流程使用真实服务端，Mock 用于测试和明确标注的演示 | 保留现有前端接口及学习会话结构 |
| P04 答疑服务端 | Vercel Serverless Functions 调用 DeepSeek API，处理结构化输出并校验来源。DeepSeek API Key 仅从服务端环境变量读取 | 浏览器通过项目答疑接口访问能力，密钥保留在服务端 |
| P04 资料检索 | 关键词检索、DeepSeek 语义重排及生成、程序校验。索引在本次请求内构建 | 当前无需 Embedding 或向量库，按长资料漏召回、规模或新 Bad Case 复评，见 DEC-010 |
| 资料分析模型 | Workflow A 复用 DeepSeek Chat。识图固定用支持视觉的 `deepseek-flash`，主题、规划和独立核验使用服务端所配文本模型 | 图片可传真实字节，无需额外 OCR 服务密钥，见 DEC-011 |
| 数据 | 前端状态 + `localStorage` | 保存任务、解析文本、进度和本次答疑历史 |
| 部署 | 前端继续使用 Vite，P04 答疑服务端使用 Vercel Serverless Functions | 维持现有前端结构并提供轻量模型接口 |

### 5.1 数据最小结构

- `project`：识别出的主题、资料支持的学习范围、已识别的内容缺口。
- `sources[]`：`id`、`title`、`type`、处理状态、原始文本或图片的提取文本。原图在当前会话中预览。
- `tasks[]`: `id`、`title`、`objective`、`steps[]`、`sourceRefs[]`、`status`。不同步骤依赖不同资料时，对应步骤附各自的 `sourceRefs[]`。
- `currentTaskIndex`：当前任务位置，初次进入时定位到 Agent 选定的入门任务。
- `messages[]`：本次学习会话的问答记录及经校验的引用，关闭再打开面板或刷新后均可恢复。
- `conflictDecision`（P1）：用户选定方案。

### 5.2 持久化与隐私边界

- Demo 的本地保存仅限单浏览器、单设备，**不承诺跨设备同步**；用户清除浏览器数据后记录可能丢失。
- 原始图片和 PDF 二进制不写入 `localStorage`。图片在当前会话中可识别和查看原图。保存来源记录、原始文本或提取文本及任务引用。刷新后原图不可用时，明确说明并展示可用的提取内容，保留来源及任务关联。
- 真实 AI 阶段，发送给模型的文件通过轻量服务端接口临时处理，尽量不长期存储用户原始附件。调用第三方模型前，提示用户内容将发送至模型服务商，实际数据处理以供应商条款为准。
- DeepSeek API Key 仅保存在 Vercel Serverless Functions 可访问的服务端环境变量中。浏览器不得直接请求 DeepSeek，密钥不得进入源码、前端公开配置、构建产物、响应、日志或版本控制。对公开 Demo 设置基础的输入长度、文件大小和调用频率限制，避免滥用和费用失控。
- 原始资料包含的“忽略所有规则”等指令仅视为待学习内容，不执行为系统指令。

### 5.3 技术约束

- 每次最多导入 10 份资料，单张图片不超过 5 MB。
- 资料太长时需要提示超出限制，不能静默截断关键内容并声称已完整分析。
- 模型输出不符合 JSON 结构或引用失效时，最多有限重试并展示清晰错误提示。
- 页面刷新后可继续当前任务；**不要求**完整的异步任务队列、后台管理或分布式存储。

## 6. 验收标准

| 编号 | 测试操作 | 通过条件 |
|---|---|---|
| AC01 | 打开首页并导入真实文本和截图，尝试添加第 11 份资料、超过 5 MB 的图片或不支持的文件 | 首页以资料导入区为主，添加资料后才显示列表，首页无学习表单、侧边栏或进度。展示合规资料状态，超限或格式不支持时说明原因 |
| AC02 | 导入未登记过的图片或真实文字资料后点击“我要开始！” | 图片经真实多模态提取；路线与原资料相符，前置关系有效且入门任务合理。仅通过程序校验的结果进入学习界面 |
| AC03 | 用至少五个不同领域及一个主题含混样例实测 | 主题、知识点和路线随资料变化。任务和步骤有可追溯引用。主题含混可简短澄清，仍不明确或资料不足时不生成固定课程 |
| AC04 | 进入正式学习界面 | 恰有三个核心侧边栏入口，面板默认收起。主区域突出当前一项任务和 2–5 个可执行步骤 |
| AC05 | 查看任务和不同资料支持的步骤，点击引用 | 每项任务至少有一条有效引用，依赖不同资料的步骤分别展示引用，引用可追溯到对应原文或提取片段 |
| AC06 | 从侧边栏打开答疑，用直接表达、口语或连续追问提问，再关闭重开、刷新并打开面板 | 调用真实 DeepSeek，围绕当前任务解释资料。逐项有据，引用可定位到原文。原回答和有效引用刷新后仍可恢复，历史任务隔离 |
| AC07 | 分别提出部分有依据、完全无依据和资料冲突的问题，并测试伪造来源或片段 | 保留独立有依据的部分，标明其余资料不足。完全无依据时拒答；冲突并列双方依据。服务端拦截伪造来源和片段，不用模型知识补充 |
| AC08 | 完成一项任务 | 进入下一项，刷新后恢复进度 |
| AC09 | 完成最后一项任务 | 显示当前资料支持的课程已结束，可回看 |
| AC10（P1，本轮不验收） | 输入存在关键冲突的两份教程 | 展示方案、AI 建议，支持用户选择后继续 |
| AC11 | 测试部分或全部资料识别失败、生成失败 | 列出失败资料及原因。部分识别成功时，经用户确认才用成功资料继续。没有可用资料、剩余资料无法形成学习路径或生成失败时，提示无法生成 |
| AC12 | 从手机和电脑访问 Demo | 核心操作均可用。采用米黄、燕麦和柔棕的温暖风格，导入区与当前任务分别是对应界面的视觉重点 |
| AC13 | 使用只覆盖主题入门内容且存在明显缺口的资料 | 开始第一项任务前说明资料支持的学习内容与已识别的缺口，无需用户设定最终目标 |
| AC14 | 分别测试省略冲突任务后仍有有效路径、以及剩余内容无法成路径的案例 | 两种情况下均不生成受冲突影响的任务。有有效路径时继续生成并显示指定冲突提示，否则明确提示无法生成可靠计划 |
| AC15 | 打开完整学习路线，回看已完成任务，再关闭面板 | 路线展示完整任务、顺序和完成状态，明确标记当前任务。关闭面板后回到当前任务，回看不改变进度 |
| AC16 | 导入文本和图片后打开学习资料，再从任务或答疑中点击引用 | 能浏览本次所有资料、查看类型和原始内容，能查看有对应关系的任务并追溯引用。刷新后若原图不可用，则说明原因并展示可用提取内容 |

验收同时覆盖 Workflow A 的 AC02、AC03、AC11、AC14，以及真实答疑的 AC06、AC07、AC16。检查浏览器只访问项目接口，DeepSeek API Key 仅在服务端可用。

**最关键的 AI Eval（至少 10 组真实/人工构造的授权测试样例）：**

1. **来源忠实度：**抽查任务和问答是否引用真实资料，有无编造教学事实。
2. **任务可执行性：**用户能否看懂“现在做什么”，是否依赖未说明的额外教程。
3. **顺序合理性：**主题、入门起点和任务顺序是否符合资料支持的内容及先修关系。
4. **边界处理：**主题模糊时能否澄清，资料覆盖有限时能否说明，无依据问题能否拒答，无效引用能否被程序拦截，P0 冲突是否按 AC14 处理。

测试记录应包含输入样例、期望行为、实际输出、问题分类及修改前后对比。**不得在作品集中虚构测试次数、效果提升或用户反馈。**

## 7. V1.0 Demo 完成定义

用户能在公开网页中，通过**真实的自选资料**独立完成以下体验：

> 一次性导入资料 → Agent 识别主题并生成带来源的学习路线 → 从当前一步开始练习 → 按需查看完整路线、原始资料或打开真实 AI 答疑 → 完成任务并继续 → 刷新后恢复当前任务、进度和答疑历史。

这即为 V1.0 的最小交付。账号体系、复杂数据库、智能爬虫、全面课程体系和商业化基础设施**均不属于完成条件**。

**作品集展示重点：**用户痛点的验证证据、为什么信任用户资料、为什么只显示下一步、AI Workflow 与来源约束、真实输出与 Eval，以及设计取舍。技术实现为这些产品判断服务。
