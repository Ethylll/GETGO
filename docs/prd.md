# PRD V1.0｜从收藏到学会——AI 技能入门 Agent（Demo）

| 项目 | 内容 |
|---|---|
| 文档版本 | V1.0 · 作品集 Demo 版 |
| 产品形态 | 响应式 Web 应用（PC、手机浏览器） |
| 产品目标 | 快速实现可交互、可演示的 AI 产品，用于 AI 产品实习作品集 |
| 核心用户 | 想学习新技能、已搜集教程，却难以整理学习路径并开始行动的初学者 |
| 核心理念 | **输入端追求信息丰富，输出端追求行动极简** |
| 开发原则 | 真实 AI 能力、完整最小闭环、低工程复杂度；不追求商业化产品完备性 |

## 1. 产品定义

### 1.1 问题与机会

目标用户会自行收藏教程、截图、笔记等资源。这些资料由用户主动筛选，往往是其愿意信任、学习的来源，但内容零散、深浅不一、顺序混乱。用户需要额外承担“整理资料、设计课程、决定下一步”的工作，增加入门心理阻力。此需求已通过前期用户访谈验证；具体访谈证据及结论单独保存在作品集研究材料中，不在本 PRD 虚构访谈数据。

### 1.2 产品定位

产品将用户上传的可信学习资料转换为**由浅入深、可以立即执行的学习任务**，并在当前任务中提供基于资料的 AI 答疑。

**一句话描述：**把你收藏的教程，变成一个带你一步步入门的私人老师。

**不是什么：**不是通用知识库、自动制课平台、思维导图/刷题工具，也不是替用户决定哪份教程“更权威”的 AI 专家。

### 1.3 不可妥协的原则

1. **Source-first：**课程和具体技能指导以用户本次上传的资料为知识依据；AI 可排序、归纳、拆分任务，不能凭空编造专业知识或虚构引用。
2. **Next Action：**默认只呈现用户眼下应做的一项任务；完整路线仅按需展开。
3. **Human-in-control：**涉及学习路径的关键资料冲突，由 AI 解释并推荐，最终由用户选择；必须提供“使用 AI 建议”。
4. **Learning by Doing：**优先形成动手实践步骤，而不是大段理论摘要。
5. **Self-paced：**不强制打卡、不设固定学习周期，不宣称用户完成任务即真正掌握技能。

## 2. V1.0 范围

### 2.1 最小业务闭环

**输入技能与目标 → 一次性导入资料 → AI 生成教学任务 → 展示下一步行动 → 用户练习/提问 → 标记完成 → 进入下一任务。**

V1.0 **假定初始上传的资料是本项目的全部资料**。生成课程后不支持继续上传、资料补齐、重新规划或自动网络搜索。允许资料本身只能支持部分学习目标：此时课程仅覆盖已有资料，不自动编造剩余内容；不设计后续补齐流程。

### 2.2 功能范围与优先级

| ID | 功能 | 优先级 | V1.0 要求 |
|---|---|---|---|
| F01 | 创建单个学习项目 | P0 | 输入技能、学习目标；基础水平可选 |
| F02 | 资料导入与识别 | P0 | 粘贴文本、上传图片/截图；提取可用文本；PDF 为 P1 |
| F03 | AI 规划课程 | P0 | 基于资料输出有序任务、步骤和来源引用 |
| F04 | 下一步任务主页 | P0 | 默认只展示当前任务，完成后进入下一项 |
| F05 | 当前任务资料内答疑 | P0 | 带任务上下文提问，引用上传资料，不足时说明不足 |
| F06 | 进度与本地保存 | P0 | 上一步/下一步、标记完成；刷新后恢复 |
| F07 | 查看原始资料引用 | P0 | 可查看被引用的原文片段/来源标题 |
| F08 | 关键冲突人机决策 | P1（加分） | AI 给出方案、推荐理由，用户选择或“使用 AI 建议” |
| F09 | 完整路线折叠查看 | P1 | 可按需打开任务列表 |
| F10 | 文本型 PDF 提取 | P1 | 可解析后按文本资料处理 |

**不做：**登录注册、多用户体系、多项目管理、服务端数据库、复杂知识图谱、独立向量数据库、自动抓取网页/视频、视频转写、补充资料、动态课程重构、能力自动测评、社区打卡、管理后台与支付。

**范围说明：**在页面与宣传中应明确图片内容可被 AI 理解；网页/视频 URL 不视为已解析内容，V1.0 不将“粘贴链接即可读取任意平台教程”作为能力承诺。

## 3. 页面与交互

### P01｜创建与资料导入（同一页面）

- 字段：技能名称（必填）、想达到的目标（必填）、当前基础（可选，默认“零基础”）。
- 资料区：可粘贴多段文本、上传 PNG/JPG/WebP 截图；列表中能看到名称、输入类型、处理状态、删除操作。
- 主要 CTA：**“生成我的第一步”**（提交前可增删资料）。
- 校验：目标或有效资料为空时禁用生成并说明原因；格式不支持、图片识别失败时提示对应文件。
- 生成时展示状态：读取资料 → 整理教学顺序 → 生成学习任务；不展示虚假的精确百分比。

### P02｜当前学习任务（最重要的界面）

默认信息层级：

1. 项目名称（较弱视觉层级）。
2. **“现在只需要做这件事” + 当前任务标题**（最突出）。
3. 任务目标和 2—5 个可执行步骤。
4. 当前步骤关联的资料来源（可展开查看原文片段）。
5. 主要按钮：**“完成，进入下一步”**。
6. 次要操作：**“我有疑问”**、**“上一项”**；可选“查看路线”。

不默认展示完整课程目录、知识图谱、大段摘要、积分或倒计时。最后一项任务完成后显示“这次资料支持的任务已完成”，允许回看；不声称用户已完全学会该技能。

### P03｜AI 答疑面板

- 从当前任务打开，显示当前任务标题及聊天消息。
- 用户提问后，AI 仅基于本次上传的资料与当前任务上下文回答；有依据时提供可点击引用。
- 资料没有答案时显示：“在你提供的资料中没有找到足够依据，因此无法可靠回答这个问题。”可追加简短说明，但不擅自引入其他教程。
- 用户关闭面板后保留本次 Demo 会话状态（建议本地保存最近消息）。

### P04｜冲突确认（P1）

仅当模型判断不同资料对**实际学习顺序或具体操作有实质影响**时触发。显示：冲突点、方案 A/B、各自来源、AI 推荐及理由。操作：**选择 A / 选择 B / 使用 AI 建议**。决策后确认课程；不修改原始资料。无关键冲突时不展示此页。

> 若 P1 未完成，Demo 不得声称已具备自动冲突解决能力。可以在作品集中作为明确的后续设计方案展示。

## 4. AI 核心能力与规则

### 4.1 Workflow A：资料理解与教学规划（P0）

**输入：**学习目标、基础水平、本次资料的 `source_id`、名称及提取文本。

**流程：**

1. 文本资料直接读取；图片由多模态模型提取其中的可用教学内容。
2. 为每份资料分配稳定 `source_id`，保留标题和原文/提取内容。
3. 调用 LLM：提取教学主题和实践动作、判断前置顺序、去重、结合目标生成任务列表。
4. 要求模型输出固定 JSON；服务端校验字段、任务数量、引用的 `source_id` 是否存在。
5. 将有效任务与来源片段一起返回前端；无有效任务时提示无法生成，不以模板课程冒充资料驱动结果。

**核心 JSON 示例（概念结构，实际开发可调整字段名）：**

```json
{
  "project_title": "吉他入门",
  "tasks": [
    {
      "id": "task_1",
      "title": "练习正确持琴",
      "objective": "根据资料完成第一次持琴练习",
      "steps": ["查看姿势示范", "按示范调整持琴姿势"],
      "source_refs": [
        { "source_id": "src_1", "excerpt": "来自原始资料的相关文字" }
      ]
    }
  ],
  "conflicts": []
}
```

**关键规则：**

- AI 可以将多个来源整合成一个任务，但不得将未经来源支持的专业教学方法当作事实。
- AI 的教学排序属于推理，可以进行，但不可把推理伪装成原作者的原话。
- `excerpt` 必须能在已提取内容中校验；校验失败则删除无效引用或重新生成，不能显示假来源。
- 图片的提取结果需保留对应图片 ID；图片内容不确定时避免输出断言。
- 首次生成目标是**可执行的任务序列**，不是全面完整的课程。

### 4.2 Workflow B：当前任务答疑（P0）

**输入：**用户问题、当前任务、资料原文/提取文本、最近对话上下文。

**流程：**选择当前任务引用的资料片段（必要时简单关键词检索全部上传文本） → 调用 LLM → 校验引用 → 返回回答。

**规则：**资料优先，回答尽量简洁，直接解决当前行动障碍；没有依据时明确承认不知道。MVP 小资料量场景可直接提供相关文本上下文，**不需要 RAG 向量库**。

### 4.3 Workflow C：冲突决策（P1）

在规划 JSON 中附带冲突候选。只有影响具体教学路径的冲突才触发用户选择；普通表达差异直接忽略。AI 给出建议并说明依据，用户最终选定。原始资料不被修改；可记录决策并用于生成或确认最终任务顺序。

### 4.4 Agent 边界

系统可以按资料和学习状态决定生成任务、提供答疑或（P1）等待用户决策，但首版主要是轻量 **LLM Workflow + 状态管理**。作品集应准确描述实际实现，**不为了营销而声称采用 Multi-Agent、自主浏览或长期记忆**。

## 5. 数据与技术方案

| 层级 | Demo 选型 | 原因 |
|---|---|---|
| 形态 | 响应式 Web App | 链接即可演示，PC/手机可用 |
| 前端 | Next.js + TypeScript | 页面与后端 API 放在一个项目 |
| UI | Tailwind CSS + shadcn/ui | 快速实现一致的组件界面 |
| 后端 | Next.js Route Handlers | API Key 留在服务端，处理模型调用 |
| 模型 | 一款支持图片输入、结构化输出的模型 API | 少量模型调用即可完成核心闭环；选型按实际质量和成本确定 |
| 数据 | 前端状态 + `localStorage` | 不做登录和数据库，保存任务、解析文本、进度和少量聊天记录 |
| 部署 | Vercel | 便于生成公开 Demo 链接 |

### 5.1 数据最小结构

- `project`: 技能、目标、基础水平。
- `sources[]`: `id`、`title`、`type`、`extractedText`、可显示的原文片段。
- `tasks[]`: `id`、`title`、`objective`、`steps[]`、`sourceRefs[]`、`status`。
- `currentTaskIndex`: 当前任务位置。
- `messages[]`: 最近的问答记录。
- `conflictDecision`（P1）：用户选定方案。

### 5.2 持久化与隐私边界

- Demo 的本地保存仅限单浏览器、单设备，**不承诺跨设备同步**；用户清除浏览器数据后记录可能丢失。
- 不将原始大图片或 PDF 二进制放入 `localStorage`（容量有限）。图片在当前会话用于识别；长期保留其提取文本和来源名称。刷新后的“查看原图”若无法支持，明确仅显示提取结果。
- 文件通过服务端临时处理，尽量不长期存储用户原始附件；调用第三方模型需提示用户内容将发送至模型服务商，实际数据处理以供应商条款为准。
- 服务端保管 API Key；对公开 Demo 设置基础的输入长度、文件大小和调用频率限制，避免滥用和费用失控。
- 原始资料包含的“忽略所有规则”等指令仅视为待学习内容，不执行为系统指令。

### 5.3 技术约束

- 可设置每次最多 10 份资料、单图不超过 5 MB 等**可配置的 Demo 配额**，不是产品理念上的“用户必须上传多少资料”。
- 资料太长时需要提示超出限制，不能静默截断关键内容并声称已完整分析。
- 模型输出不符合 JSON 结构或引用失效时，最多有限重试并展示清晰错误提示。
- 页面刷新后可继续当前任务；**不要求**完整的异步任务队列、后台管理或分布式存储。

## 6. 验收标准

| 编号 | 测试操作 | 通过条件 |
|---|---|---|
| AC01 | 输入目标并上传数份真实文本/截图 | 文件被正确接收并显示处理状态 |
| AC02 | 点击“生成我的第一步” | 使用真实模型 API 生成任务，而非写死模板 |
| AC03 | 使用未见过的新资料测试 | 计划能随资料变化，并可追溯原文 |
| AC04 | 查看当前任务 | 默认仅突出一项可执行行动，步骤清晰 |
| AC05 | 点击资料引用 | 展示对应真实来源或提取片段；不存在虚构引用 |
| AC06 | 输入资料中可回答的问题 | AI 能用资料回答，并正确标注来源 |
| AC07 | 输入资料中没有依据的问题 | AI 说明资料不足，不凭空给出具体教学指导 |
| AC08 | 完成一项任务 | 进入下一项，刷新后恢复进度 |
| AC09 | 完成最后一项任务 | 显示当前资料支持的课程已结束，可回看 |
| AC10（P1） | 输入存在关键冲突的两份教程 | 展示方案、AI 建议，支持用户选择后继续 |
| AC11 | AI 生成失败或资料无法解析 | 提供明确错误提示，不假装成功 |
| AC12 | 从手机或电脑访问 Demo | 核心操作能够正常使用 |

**最关键的 AI Eval（至少 10 组真实/人工构造的授权测试样例）：**

1. **来源忠实度：**抽查任务和问答是否引用真实资料，有无编造教学事实。
2. **任务可执行性：**用户能否看懂“现在做什么”，是否依赖未说明的额外教程。
3. **顺序合理性：**是否符合资料中明确的先修关系和用户目标。
4. **边界处理：**无依据问题能否承认不足；冲突场景能否按 P1 规则处理（若已实现）。

测试记录应包含输入样例、期望行为、实际输出、问题分类及修改前后对比。**不得在作品集中虚构测试次数、效果提升或用户反馈。**

## 7. V1.0 Demo 完成定义

用户能在公开网页中，通过**真实的自选资料**独立完成以下体验：

> 创建学习目标 → 上传一批资料 → AI 生成带来源的渐进式任务 → 只看到当前下一步 → 实际练习并提问 → 完成任务并继续。

这即为 V1.0 的最小交付。账号体系、复杂数据库、智能爬虫、全面课程体系和商业化基础设施**均不属于完成条件**。

**作品集展示重点：**用户痛点的验证证据、为什么信任用户资料、为什么只显示下一步、AI Workflow 与来源约束、真实输出与 Eval，以及设计取舍。技术实现为这些产品判断服务。
