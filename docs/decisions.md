# V1.0 产品决策记录

本文记录方案取舍及原因，备选方案按旧版需求和本轮决策中的对照方向整理。当前功能范围、交互细节和验收标准以 [PRD](prd.md) 为准。

## DEC-001｜取消用户主动设定学习目标

- **决策背景**　用户已经搜集了资料，但常常还不知道学习顺序或入门起点。要求他们先描述最终目标和基础水平会提高开始学习的门槛。
- **曾考虑的备选方案**　沿用旧版创建表单，让用户填写技能和目标、选填基础水平；或以资料为入口，由 Agent 推断主题，必要时再澄清。
- **最终决策**　用户只需粘贴文本或上传图片。Agent 从资料识别主题、整理知识点和前置关系，选择有依据的入门起点。主题无法可靠判断时进行简短澄清。
- **设计原则**　把组织资料和安排起点的工作交给 Agent。澄清仅用于解决具体歧义。
- **当前状态**　已确认。

## DEC-002｜完整学习路线采用主动查看模式

- **决策背景**　完整路线便于理解顺序和进度，初次进入时展开全部任务会分散用户对当前行动的注意力。
- **曾考虑的备选方案**　默认展开完整路线；或默认聚焦当前任务，把完整路线放在用户主动打开的面板中。旧版将路线查看列为 P1，存在首轮无法查看的取舍。
- **最终决策**　完整学习路线和主动查看入口均纳入 P0。面板默认收起，打开后可查看全部任务、顺序、状态和当前任务，并回看已完成任务。
- **设计原则**　当前行动优先。全局信息在用户需要时可达，回看后可继续当前学习。
- **当前状态**　已确认。

## DEC-003｜采用温暖、亲切的视觉风格

- **决策背景**　用户需要一个能直接交付资料并开始学习的空间。复杂布局和装饰会稀释导入操作的视觉重点。
- **曾考虑的备选方案**　沿用旧版通用工具型 Web 应用风格，或采用更温暖、安静的个人学习空间。复杂仪表盘和卡通化表达均从本轮方向中排除。
- **最终决策**　以米黄、燕麦和柔棕为主，留出适当空间。首页集中呈现产品简介、导入入口与必要反馈，添加资料后再显示列表。
- **设计原则**　视觉层级服务于当前任务，用色彩、留白和排版营造陪伴感。
- **当前状态**　已确认。

## DEC-004｜正式学习界面采用三个侧边栏入口

- **决策背景**　学习中可能需要查看整体进度、回查原始内容或提问。这些操作都应易于访问，同时保留当前任务作为主要视图。
- **曾考虑的备选方案**　沿用旧版在任务正文分散布置答疑按钮、可选路线入口及引用；或在正式学习界面提供固定的独立入口。
- **最终决策**　分析完成后才显示侧边栏，核心入口为「完整学习路线」「学习资料」「AI 答疑」。各面板按需打开，关闭后可回到当前任务。学习资料面板支持原始资料浏览和关联任务回查。
- **设计原则**　入口位置稳定，辅助信息按需出现，首页集中处理资料导入。
- **当前状态**　已确认。

## DEC-005｜AI 答疑严格遵循用户资料来源约束

- **决策背景**　用户主动选择了学习资料，答疑需要让用户核对结论来自哪里。模型可能用自身知识补全答案，也可能生成看似合理但无法验证的引用。
- **曾考虑的备选方案**　允许模型用常识或外部搜索补充资料；仅在提示词中要求遵循资料；或同时约束回答上下文并对来源进行程序校验。
- **最终决策**　事实性回答只使用本次资料，以可验证的来源 ID 和相关片段提供引用。真实 AI 结合检索、上下文约束和程序校验。引用无法验证时拒绝展示，结论缺少依据时明确说明资料不足。
- **设计原则**　来源可追溯、事实可核对，资料不足时如实反馈。
- **当前状态**　已确认。

## DEC-006｜P04 开发阶段直接接入真实 AI 答疑

- **决策背景**　完整 Mock 答疑可以验证面板交互，但预设答案无法验证真实提问时的资料检索、事实忠实度、引用准确性和资料不足时的拒答。直接接入真实模型，才能在 P04 验证用户能否凭自己的资料解决当前任务中的疑问。
- **曾考虑的备选方案**　先实现完整 Mock 答疑，再接入真实 AI。检索方案比较了 JavaScript 关键词检索与段落匹配，以及基于向量数据库的检索。首版只检索本次导入的少量资料，轻量 RAG 便于逐段核对结果。向量方案会引入嵌入、索引和额外存储，留待证据表明有需要时再评估。
- **最终决策**　P04 正式答疑直接接入 DeepSeek API，通过 Vercel Serverless Functions 发起模型请求。DeepSeek API Key 仅保存在服务端环境变量中。第一版采用 JavaScript 关键词检索和段落匹配，从本次导入资料中提取与当前任务及问题有关的片段，模型以结构化数据返回回答或拒答及对应引用。Mock 保留用于测试和模拟异常场景。
- **引用校验**　结构化输出便于程序校验，但模型仍可能生成不存在的来源 ID，或把改写的内容当作原文引用。服务端必须检查来源 ID 属于本次导入的资料，并在对应原文或提取文本中核对片段。无法获得可靠依据时明确拒答，禁止用模型自身知识补充资料中不存在的事实。
- **影响**　P04 正式验收包含真实模型调用、资料内答疑、引用追溯、无依据拒答和会话恢复。核心流程继续围绕当前任务，关闭再打开面板及刷新后均可恢复答疑历史。P01、P02、P03 的已验收范围保持不变。本条中的 P04 指开发阶段，PRD 第 3 节沿用原有页面编号。
- **后续演进**　P04.2.1 按 DEC-007 升级检索，按 DEC-008 调整核验和存储。此处保留首次接入时的选型。

## DEC-007｜答疑升级为关键词和语义重排的混合检索

- **背景**　审计发现 P04.2.1 之前的零词面命中会在模型调用前拒答。「弹奏时怎么摆放这家伙才能少抖一些」及「刚才那只胳膊呢」可用固定吉他资料复现。任务标题只能给已命中的片段加排序分。
- **备选方案**　扩充纯关键词词表只增加少量成本，泛化和指代仍受限。独立 Embedding 服务（例如 OpenAI Embeddings）加会话内向量可扩展召回，但需要独立密钥、导入时批量向量化和每轮问题向量化，增加网络往返、按输入量计费以及第三方资料传输。可在会话内复用文档向量，但跨 Vercel 实例复用还需持久化策略。托管向量库另需服务配置、索引费或维护成本，必须按会话隔离并实现到期或删除清理。用 DeepSeek 重排可沿用 Chat API 和现有密钥，并让模型解析口语和历史语境。参考 [DeepSeek API 目录](https://api-docs.deepseek.com/) 和 [OpenAI Embeddings](https://developers.openai.com/api/docs/guides/embeddings)。
- **最终决定**　关键词、任务相关段落、邻段和跨来源候选限定为 14 段，用 DeepSeek Chat 做语义重排。只融合语义评分至少 2 的段，正式证据最多 8 段。维持关键字检索通道。核对官方 API 后，本轮未采用 DeepSeek Embedding、独立 Embedding 服务和向量数据库。以后按公开 Demo 的实测召回、延迟、费用和资料范围决定是否采用。
- **影响**　请求内建立片段索引。客户端刷新后从 localStorage 恢复资料和历史，服务端用本轮资料重建索引，索引在请求结束后释放。诊断只记录请求标识、片段哈希、评分、数量和阶段，不记录文本、标题、题目或密钥。检索新增一次有界模型调用，大资料中的口语问题仍可能漏掉候选。详见 [AI 评测](./ai-evaluation.md)。
- **状态**　已实现，有限真实样例已验证。

## DEC-008｜引用精确校验、逐项教学核验与原文恢复

- **背景**　DEC-005、DEC-006 只要求事实来源可追溯，并逐字查验引用。P04.2 v1 的 Codex 实现额外要求正文等于引用拼接。当前可见答疑实现首见于 `a0078d6`，提交已是 v2。BC-001 当时放开了服务端正文，审计发现存储仍在执行全文相等检查，且数值字符串比较和整答核对会错弃有效内容。
- **备选方案**　保持逐字摘录易于验证但不能完成教学解释；只依赖单次模型自检无法独立过滤事实；整答二次核对能拒绝越界内容，但同时丢掉独立有依据的部分。
- **最终决定**　分开做逐字引文校验与逐项语义核验。每项关联完整证据，错项不显示，保留有效项并提示缺口。常见数值形式先做等价核对，再核对对象、单位和条件。存储保留服务端通过核验的自然语言正文，保存和读取都继续查验引用，兼容旧摘录。
- **影响**　不改变引用定位。历史消息只用于理解问题，每轮重检索。旧逻辑从未持久化的消息无法恢复。模型仍可能错误评估语义支持。
- **状态**　持久化和逐项核验已通过程序回归，见 [AI 评测](./ai-evaluation.md)。

## DEC-009｜分离程序回归、检索和真实模型评测

- **背景**　BC-001 的 Mock 预设输出只能验证程序分支。少量吉他实测也不能说明任意资料的回答率及忠实度。
- **备选方案**　只记录人工截图难以回归，只运行 Mock 无法判断模型效果。
- **最终决定**　维护固定资料、人工标注证据、预期状态和可执行真实评测。程序测试、RAG 算法、真实模型、浏览器端到端分开计量。后续 Bad Case 加入同一评测集并扩展到不同资料和主题。
- **影响**　可复查召回、误召回、支持覆盖、引用定位和严格拒答；已有数据只作为当前样本集结果。见 [AI 评测](./ai-evaluation.md) 和 [Prompt 记录](./prompt-evaluation.md)。
- **状态**　初始评测集已建立并运行。
