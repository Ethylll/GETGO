# GETGO 产品决策记录

本文记录方案取舍及原因，备选方案按旧版需求和本轮决策中的对照方向整理。当前功能范围、交互细节和验收标准以 [PRD](prd.md) 为准。

## DEC-001｜取消用户主动设定学习目标

- **决策背景**　用户已经搜集了资料，但常常还不知道学习顺序或入门起点。要求他们先描述最终目标和基础水平会提高开始学习的门槛。
- **曾考虑的备选方案**　沿用旧版创建表单，让用户填写技能和目标、选填基础水平；或以资料为入口，由 Agent 推断主题，必要时再澄清。
- **最终决策**　用户只需粘贴文本或上传图片。Agent 从资料识别主题、整理知识点和前置关系，选择有依据的入门起点。主题无法可靠判断时进行简短澄清。
- **设计原则**　把组织资料和安排起点的工作交给 Agent。澄清仅用于解决具体歧义。
- **当前状态**　已确认。

## DEC-002｜完整学习路线采用主动查看模式

- **决策背景**　完整路线便于理解顺序和进度，初次进入时展开全部任务会分散用户对当前行动的注意力。
- **曾考虑的备选方案**　默认展开完整路线；或默认聚焦当前任务，把完整路线放在用户主动打开的面板中。旧版将路线查看列为 P1，存在首轮无法查看的取舍。
- **最终决策**　完整学习路线和主动查看入口均纳入 P0。面板默认收起，打开后可查看全部任务、顺序、状态和当前任务，并回看已完成任务。
- **设计原则**　当前行动优先。全局信息在用户需要时可达，回看后可继续当前学习。
- **当前状态**　已确认。

## DEC-003｜采用温暖、亲切的视觉风格

- **决策背景**　用户需要一个能直接交付资料并开始学习的空间。复杂布局和装饰会稀释导入操作的视觉重点。
- **曾考虑的备选方案**　沿用旧版通用工具型 Web 应用风格，或采用更温暖、安静的个人学习空间。复杂仪表盘和卡通化表达均从本轮方向中排除。
- **最终决策**　以米黄、燕麦和柔棕为主，留出适当空间。首页集中呈现产品简介、导入入口与必要反馈，添加资料后再显示列表。
- **设计原则**　视觉层级服务于当前任务，用色彩、留白和排版营造陪伴感。
- **当前状态**　已确认。

## DEC-004｜正式学习界面采用三个侧边栏入口

- **决策背景**　学习中可能需要查看整体进度、回查原始内容或提问。这些操作都应易于访问，同时保留当前任务作为主要视图。
- **曾考虑的备选方案**　沿用旧版在任务正文分散布置答疑按钮、可选路线入口及引用；或在正式学习界面提供固定的独立入口。
- **最终决策**　分析完成后才显示侧边栏，核心入口为「完整学习路线」「学习资料」「AI 答疑」。各面板按需打开，关闭后可回到当前任务。学习资料面板支持原始资料浏览和关联任务回查。
- **设计原则**　入口位置稳定，辅助信息按需出现，首页集中处理资料导入。
- **当前状态**　已确认。

## DEC-005｜AI 答疑严格遵循用户资料来源约束

- **决策背景**　用户主动选择了学习资料，答疑需要让用户核对结论来自哪里。模型可能用自身知识补全答案，也可能生成看似合理但无法验证的引用。
- **曾考虑的备选方案**　允许模型用常识或外部搜索补充资料；仅在提示词中要求遵循资料；或同时约束回答上下文并对来源进行程序校验。
- **最终决策**　事实性回答只使用本次资料，以可验证的来源 ID 和相关片段提供引用。真实 AI 结合检索、上下文约束和程序校验。引用无法验证时拒绝展示，结论缺少依据时明确说明资料不足。
- **设计原则**　来源可追溯、事实可核对，资料不足时如实反馈。
- **当前状态**　已确认。

## DEC-006｜P04 开发阶段直接接入真实 AI 答疑

- **决策背景**　完整 Mock 答疑可以验证面板交互，但预设答案无法验证真实提问时的资料检索、事实忠实度、引用准确性和资料不足时的拒答。直接接入真实模型，才能在 P04 验证用户能否凭自己的资料解决当前任务中的疑问。
- **曾考虑的备选方案**　先实现完整 Mock 答疑，再接入真实 AI。检索方案比较了 JavaScript 关键词检索与段落匹配，以及基于向量数据库的检索。首版只检索本次导入的少量资料，轻量 RAG 便于逐段核对结果。向量方案会引入嵌入、索引和额外存储，留待证据表明有需要时再评估。
- **最终决策**　P04 正式答疑直接接入 DeepSeek API，通过 Vercel Serverless Functions 发起模型请求。DeepSeek API Key 仅保存在服务端环境变量中。第一版采用 JavaScript 关键词检索和段落匹配，从本次导入资料中提取与当前任务及问题有关的片段，模型以结构化数据返回回答或拒答及对应引用。Mock 保留用于测试和模拟异常场景。
- **引用校验**　结构化输出便于程序校验，但模型仍可能生成不存在的来源 ID，或把改写的内容当作原文引用。服务端必须检查来源 ID 属于本次导入的资料，并在对应原文或提取文本中核对片段。无法获得可靠依据时明确拒答，禁止用模型自身知识补充资料中不存在的事实。
- **影响**　P04 正式验收包含真实模型调用、资料内答疑、引用追溯、无依据拒答和会话恢复。核心流程继续围绕当前任务，关闭再打开面板及刷新后均可恢复答疑历史。P01、P02、P03 的已验收范围保持不变。本条中的 P04 指开发阶段，PRD 第 3 节沿用原有页面编号。
- **后续演进**　P04.2.1 按 DEC-007 升级检索，按 DEC-008 调整核验和存储。此处保留首次接入时的选型。

## DEC-007｜答疑升级为关键词和语义重排的混合检索

- **背景**　审计发现 P04.2.1 之前的零词面命中会在模型调用前拒答。「弹奏时怎么摆放这家伙才能少抖一些」及「刚才那只胳膊呢」可用固定吉他资料复现。任务标题只能给已命中的片段加排序分。
- **备选方案**　扩充纯关键词词表只增加少量成本，泛化和指代仍受限。独立 Embedding 服务（例如 OpenAI Embeddings）加会话内向量可扩展召回，但需要独立密钥、导入时批量向量化和每轮问题向量化，增加网络往返、按输入量计费以及第三方资料传输。可在会话内复用文档向量，但跨 Vercel 实例复用还需持久化策略。托管向量库另需服务配置、索引费或维护成本，必须按会话隔离并实现到期或删除清理。用 DeepSeek 重排可沿用 Chat API 和现有密钥，并让模型解析口语和历史语境。参考 [DeepSeek API 目录](https://api-docs.deepseek.com/) 和 [OpenAI Embeddings](https://developers.openai.com/api/docs/guides/embeddings)。
- **最终决定**　关键词、任务相关段落、邻段和跨来源候选限定为 14 段，用 DeepSeek Chat 做语义重排。只融合语义评分至少 2 的段，正式证据最多 8 段。维持关键字检索通道。核对官方 API 后，本轮未采用 DeepSeek Embedding、独立 Embedding 服务和向量数据库。以后按公开 Demo 的实测召回、延迟、费用和资料范围决定是否采用。
- **影响**　请求内建立片段索引。客户端刷新后从 localStorage 恢复资料和历史，服务端用本轮资料重建索引，索引在请求结束后释放。诊断只记录请求标识、片段哈希、评分、数量和阶段，不记录文本、标题、题目或密钥。检索新增一次有界模型调用，大资料中的口语问题仍可能漏掉候选。详见 [AI 评测](./ai-evaluation.md)。
- **状态**　已实现，有限真实样例已验证。

## DEC-008｜引用精确校验、逐项教学核验与原文恢复

- **背景**　DEC-005、DEC-006 只要求事实来源可追溯，并逐字查验引用。P04.2 v1 的 Codex 实现额外要求正文等于引用拼接。当前可见答疑实现首见于 `a0078d6`，提交已是 v2。BC-001 当时放开了服务端正文，审计发现存储仍在执行全文相等检查，且数值字符串比较和整答核对会错弃有效内容。
- **备选方案**　保持逐字摘录易于验证但不能完成教学解释；只依赖单次模型自检无法独立过滤事实；整答二次核对能拒绝越界内容，但同时丢掉独立有依据的部分。
- **最终决定**　分开做逐字引文校验与逐项语义核验。每项关联完整证据，错项不显示，保留有效项并提示缺口。常见数值形式先做等价核对，再核对对象、单位和条件。存储保留服务端通过核验的自然语言正文，保存和读取都继续查验引用，兼容旧摘录。
- **影响**　不改变引用定位。历史消息只用于理解问题，每轮重检索。旧逻辑从未持久化的消息无法恢复。模型仍可能错误评估语义支持。
- **状态**　持久化和逐项核验已通过程序回归，见 [AI 评测](./ai-evaluation.md)。

## DEC-009｜分离程序回归、检索和真实模型评测

- **背景**　BC-001 的 Mock 预设输出只能验证程序分支。少量吉他实测也不能说明任意资料的回答率及忠实度。
- **备选方案**　只记录人工截图难以回归，只运行 Mock 无法判断模型效果。
- **最终决定**　维护固定资料、人工标注证据、预期状态和可执行真实评测。程序测试、RAG 算法、真实模型、浏览器端到端分开计量。后续 Bad Case 加入同一评测集并扩展到不同资料和主题。
- **影响**　可复查召回、误召回、支持覆盖、引用定位和严格拒答；已有数据只作为当前样本集结果。见 [AI 评测](./ai-evaluation.md) 和 [Prompt 记录](./prompt-evaluation.md)。
- **状态**　初始评测集已建立并运行。

## DEC-010｜正式采用当前轻量 RAG

- **背景**　P04.2.1 的 10 道真实 DeepSeek 题符合预期，11 个标注证据段全部召回。用户人工验收反馈当前效果暂时可以接受。
- **备选方案**　保持当前方法；引入 Embedding 和会话内向量索引；采用向量库、关键词与向量混合检索或更复杂的 Reranker。
- **决定及理由**　正式采用关键词检索、DeepSeek 语义重排、DeepSeek 生成和程序校验。范围仍限本次导入资料，答疑核对沿用逐项核验。现阶段优先完成从真实资料到计划和答疑的闭环，向量化的附加 API、索引、存储和部署成本缺少收益证据。
- **重新评估条件**　导入规模扩大、标注召回下滑、长文漏召回，或用户发现新的检索 Bad Case 时，比较 Embedding、向量数据库、关键词与向量混合检索和更复杂的重排序。DEC-007 和既有实验保留。

## DEC-011｜正式学习规划迁移至同一 DeepSeek 服务

- **背景**　统一前端入口原先直接调用 `mockAnalysisService.js`。文字读取保留了原文，但主题、提取、前置关系、任务、覆盖缺口和冲突由预设吉他场景决定。图片只匹配同一个登记样本。
- **备选方案**　复用 DeepSeek Vision；用阿里云百炼视觉模型；接独立 OCR 再送文本模型。阿里云需要额外凭据与地域配置。独立 OCR 适合逐字文本，但对原创图示理解还需另一模型。
- **决定及理由**　新增 Vercel `/api/analysis`。图片固定用官方支持视觉的 `deepseek-flash`。主题识别、规划和独立任务核验沿用 `DEEPSEEK_MODEL`，默认同为 `deepseek-flash`。服务端复用 `DEEPSEEK_API_KEY`。用现有 Fetch 和原始上传字节，无需额外服务、密钥或数据库。参见 [DeepSeek Vision](https://api-docs.deepseek.com/guides/vision/) 和 [阿里云百炼视觉理解](https://help.aliyun.com/zh/model-studio/vision)。
- **影响**　前端仍经 `analysisService` 使用原有状态与来源结构。图片逐张临时上传，超过 4 MiB 时浏览器压缩上传副本以避免常见的 Vercel 请求体限制，原图留在当前页。文字不改写。计划必须经过双端结构与引用校验，服务端独立核验教学依据和冲突。Mock 仅在测试、标明的演示与旧会话兼容中保留。
- **Bad Case**　BC-005 仅有意向误触发澄清，主题 Prompt 先区分有无实质资料；BC-006 局部冲突误阻断整条路线，增加一次独立任务恢复；BC-007 单动作被硬拆并补出资料外比较，增加相邻动作合并约束与独立核验；BC-008 把泛化动作当明确主题，缺关键对象时先问。固定样例复验符合预期，仍存在的模型风险见 [AI 评测](./ai-evaluation.md)。

## DEC-012｜V2 学习日、练习依赖与旧会话兼容

- **背景与备选**　可用自然日自动调度、固定任务量，或采用主动推进学习日及任务配额。旧会话可重生路线、补造日历映射，或保持兼容。
- **Q1 已确认**　默认按 Day N，只有资料明确要求自然时间间隔时按实际时间。每日默认 30 分钟、最多 5 项，可配置，无需新增设置页。时长由初始 Workflow 合理安排，无需填满配额。完成任务后，剩余配额内新解锁内容只能成为选学，不能自动追加必做。未完成不无限积压，漏练不加量，每日有明确结束边界。
- **Q2 已确认**　只按计划明示的可观察入门动作或自检反馈解锁。无明确能力门槛时，周期练习与新学习并行。单次练习完成、满足后续条件和技能掌握分别表达，次数只作为记录。
- **Q3 已确认**　优先最低成本兼容，保留 V1 进度、问答及资料，不补造 Day、时长或强制迁移路线。新项目用 V2。缺数据时允许 V1 兼容视图，避免为旧数据建立复杂迁移。
- **影响及验证**　计划协议要区分时间单位与证据，调度要区分必做和选学；保留 V1 读路径。通过混合路线、主动切日、漏练和刷新回归验证。

## DEC-013｜V2 项目级答疑与教学行动权限

- **背景与备选**　可只对当前任务答疑并要求确认一切调整，或同时接住项目级反馈，并按影响与已有记录决定权限。
- **Q4 已确认**　无当前任务也可以基于项目资料提问，记录关联项目和学习日，任务可空。普通知识提问不触发即时观察；整体计划太难、没时间或方向不适合等项目级反馈进入后续观察上下文，由 Agent 自行判断是否干预。
- **Q5 已确认**　教学提示、重新讲解和不覆盖历史的辅助练习可直接提供。未来练习时长、频率的低影响调整可自动生效并说明，未开始实例在合法范围内也可自动调整。已开始的当前任务如需实质改变，或涉及主线、关键依赖和重要任务移除，均须用户确认。调整无关联记录时可撤销；已有学习记录或反馈时通过新变更恢复，保留历史。
- **影响及验证**　统一轻量权限校验，保留模型自主选择与真实行动回执。通过无任务答疑、项目级反馈、拦截越权、确认及撤销前后记录验证。

## DEC-014｜V2 阶段自主交付与最终人工验收

- **背景与备选**　逐阶段等待人工验收有较高切换成本。V2 改用阶段自主测试和最终统一人工验收，保留独立检查点。
- **已确认**　按 V2-P01 至 V2-P06 一次只做一个阶段。结束前自测、自审、更新证据和进度，并建立单独 Git Commit。用户回复「继续」授权下个阶段，既有确认无需重复，阶段结果不能表述为人工验收。未经授权不 Push。
- **影响及验证**　每次开始都重读 AGENTS、原始规格、计划、矩阵、相关决策和上一阶段实际记录及代码。98 项 ID 持续保留，跨阶段功能未验证时如实记录。V2-P06 后提供最终验收指南，人工验收和独立覆盖审查由用户另行发起。

## DEC-015｜从学习启动扩展到持续技能学习

- **背景与证据**　V1 的用户验证表明，用户愿意尝试从碎片资料生成路线，但大多数在完成几个步骤后停止使用。产品团队判断线性推进和静态安排可能造成后续决策负担，尚无量化证据证明这两点是唯一原因。
- **备选方案**　扩大上传数量、优化边缘交互，或继续保留轻量导入，重点改造学习阶段。前者能改善起步体验，对反复练习和遇到困难后的调整帮助有限。
- **已确认**　保留资料驱动起点，V2 加入今日学习、周期练习和受限教学调整。用可承担的日任务减少持续学习中的决策成本。
- **预期与风险**　用户更容易判断今天学什么、何时适合继续。过密安排或提示也可能增加负担，依靠明确日边界及默认保持计划降低风险。
- **后续验证**　另行检验持续学习行为及对困难的缓解。有限功能试跑只说明流程连通。

## DEC-016｜一次性任务和周期练习并行

- **背景**　绘画、乐器等技能需要反复练习，部分知识按顺序只需完成一次。一次操作完成不能证明熟练。
- **备选方案**　保留单线任务、把每次练习预展开成长路线，或由同一个计划承载两种任务并由程序按日安排。预展开会放大计划长度，也会混淆未完成和应继续重复。
- **已确认**　今日学习是默认入口。混合任务按必要依赖、Day N 或明确的自然时间间隔调度。用户即使有未完成任务也可推进，原日和实例保留。配额与依赖由确定性程序处理。DEC-012 的优先级、选学、时间单位和旧数据兼容规则继续生效。
- **预期与风险**　关注当日合适的动作，同时支持持续练习与新内容并行。频率不当可能过松或过紧，原文约束、自检和后续复核提供调整依据。
- **后续验证**　检验练习安排、学习体验和持续使用。单次完成、自检与掌握分别判断。

## DEC-017｜引入有限自治 Learning Agent

- **背景**　静态路线无法预知时间限制、理解困难或练习表现。答疑能够解释资料，但无法单独把合法调整应用到学习过程。
- **备选方案**　固定规则容易验证，但会把漏练次数直接当作干预理由。固定 Workflow 容易限制成一次分类。完全自治可以覆盖更多操作，扩大意外全量改动和历史损坏风险。有限自治允许模型综合上下文并运行明确的少量工具。
- **已确认**　选择一个有限 Agent。它读取近期和相关学习事实、问答及资料，默认维持计划，自主选择指导、澄清、拆解、练习调整、重排或自检，按真实回执继续、等待或结束。执行器负责证据和权限、预算、确认和历史保护。沿用 DEC-013 的影响分级与撤销边界。
- **预期与风险**　局部帮助能落到具体任务，模型可能过度干预、误读反馈，或增加延迟和成本。采用短回合和独立核验，已经调整但尚未实践时默认等待。失败时沿用有效安排。
- **后续验证**　检验干预时机、行动选择、问题缓解、计划稳定及模型成本。通过功能测试不代表教学判断普遍有效。

## DEC-018｜保留 Workflow、确定性程序与 Agent 的混合架构

- **背景**　初始资料理解、每日调度与开放学习反馈的推理需求不同。复用 V1 的真实 DeepSeek、轻量 RAG 和来源定位可以减少额外工程与数据处理。
- **备选方案**　纯规则难处理语义反馈；所有步骤交给模型会让每日调度和完成状态变得不稳定；采用新 Agent 框架、多 Agent、独立检索或记忆服务则增加集成和运维成本。
- **已确认**　初始路线继续用结构化 Workflow 和独立核验。配额、依赖、学习日、权限及状态写入交给程序。有限 Agent 处理是否干预、具体教学行动及后续观察。复用 React、Vite、Vercel、DeepSeek、RAG 和本地快照，不引入账号、数据库、专业评分或额外记忆基础设施。
- **预期与风险**　把可预测行为留在程序，把语义判断留给模型。多步核验仍增加耗时；混合设计需要检查观察、回执与本地修订是否一致。
- **后续验证**　以真实功能样例和状态回归检查职责边界，后续评估持续学习价值及响应费用，再判断是否需要扩展技术栈。

## DEC-019｜Demo 采用手动推进的模拟自然日

- **背景与备选**　真实时钟要求为 48 小时间隔实际等待，拖长多日演示、验收和后续功能评测。比较保留真实时钟、增加单独的测试时钟及让所有 Demo 学习使用同一个模拟时钟。
- **已确认**　V2 每点击一次页角「下一日」，模拟时间推进 24 小时，可随时操作。封存原日和问答，按有效计划排下一日，并提供 Agent 观察机会。没有后台跨日。此条替代 DEC-012 Q1 和 DEC-016 中关于自然间隔使用真实时间的口径，保留其配额、依赖、选学与旧会话规则。
- **时间和记录**　明确的原文间隔用模拟分钟；缺少原文依据的频率标为 AI 教学建议。真实操作时间保留为技术记录。Day 1 模拟分钟为零，Day 3 为 2880；旧 V2 按既有日编号恢复模拟时间，原结果与真实时间不重写，V1 仍为线性兼容视图。
- **观察**　封存日已完成、未开始及进行中均保存实际状态。后两类是该日未完成证据，进行中保留已尝试含义；开放日暂未完成不提前判定。Agent 可读取多日证据，原因和行动由 Agent 结合问答及表现自主判断。
- **预期与验证**　在同一实际会话验证两次推进、48 小时练习和多日观察；同时明确这是模拟学习日，避免将推进次数解释为真实自然日或使用留存。
