# GETGO AI 答疑评测

## 方法

1. **程序回归**　`node --test` 使用 Mock 上游测试协议、引用、逐项核验、隔离和持久化。验证程序如何处理输出。
2. **RAG 算法**　[固定资料和标注](../tests/fixtures/chat-evaluation.json) 的证据标记为 `sourceId:段号`，段号从 0 开始。程序验证标注段进入有界候选和融合规则。词法基线与真实语义重排结果另行量化。
3. **真实 DeepSeek**　`node --env-file-if-exists=.env.local scripts/evaluate-chat.js` 使用应用的真实服务端处理器和固定合成资料。可传入用空格分隔的样例 ID。脚本记录词法与实际召回、状态、引用定位、耗时和合成样例回答。人工复核结论是否正确、语言是否易懂和是否合理拒答。
4. **端到端**　从浏览器导入资料进入 P02 学习计划，打开发问，经实际检索和模型后点击引用。刷新检查完整正文、状态和原文引用，再追问，最后推进任务检查隔离。浏览器测试与处理器测试分别记录。

资料范围包括持琴、练习时长、调音、冲突版本和无关清洁说明。多轮样例提供同任务历史。时间以客户端日期记录，供应商模型和输出具有变化。

## 初始结果 · 2026-11-20

真实 DeepSeek 对以下 10 个样例均返回 HTTP 200。正文、状态及拒答是否恰当按合成资料人工核查。引用在程序中逐字回查并经现有来源定位函数解析。

- **召回**　词法通道找回标注的 5/11 段，约 45%。融合后为 11/11 段，本组标注外结果 0 段。两道无依据负例语义筛选均无返回，词法通道在 A03 曾高亮一个同主题段。真实调用的单例耗时在约 0.5–3.5 秒之间，仅供此环境对照。
- **参数选择**　候选上限 14 段，语义门槛为 2（实际提供答案、条件或冲突依据），选入生成的上限为 8 段。以本组实际排序回放，仅保留 Top-1 会在 R05、R06、A02 各缺一段。初始组不足以证明更大语料下的最优 Top-K 或阈值。
- **输出质量**　预期状态 10/10，所有返回引用可定位。有效问答的措辞清楚，也保留了时长适用条件与冲突两方。未观察到本组的资料外断言；这不代表真实模型无误判。
- **程序和构建**　45 项测试通过，包含 P02 资料分析、P03 进度和已验收的来源定位，以及新增的答疑、会话隔离和历史恢复。Vite 生产构建通过。
- **浏览器端到端**　Edge 实际导入吉他演示文档，进入现有 Mock 学习路线。答疑请求经真实服务端处理器发给 DeepSeek。口语问题返回自然答案，点击引用高亮了原文。刷新后正文原样恢复，接着能回答「那只胳膊呢」。资料外问题拒答，推进任务后历史隔离，320 px 页面无横向溢出。浏览器通过本地 Vite 转发调用处理器，未进行远端部署验证。
- **隔离与限制**　运行时不会跨请求共享资料索引。独立 Embedding 与向量数据库本轮未采用，本结果不包含 Embedding 评测。后续样例应扩展到不同学科、长资料及更复杂的暗示性问题。新增 Bad Case 时保留固定原文、问题、预期证据、预期状态、实际结果和版本号。
